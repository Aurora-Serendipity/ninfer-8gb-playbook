# NInfer 8 GB Playbook · 在 8 GB 笔记本显卡上跑 27B 本地大模型

> 一套**已实测验收**的本地大模型部署与调优方案：**NInfer 引擎 + Bonsai 2 27B 三进制量化模型**，
> 跑在 **RTX 4060 Laptop（8 GB 显存 / sm_89）** 上。
>
> **本仓库的全部数字都来自真机实测**——包括**负结果**（哪一种改法会变慢、哪一次实验是白做的）。
> 我们不复制上游文档，只写自己量到的东西，并注明哪些结论来自上游、哪些是本机验证。

## 快速开始

```text
1) 放好三样东西（目录可整体搬走，脚本内部用相对路径）
   10-engine\engine\ninfer-serve-89.exe      ← 引擎（sm_89）
   20-model\models\<模型>.ninfer             ← 模型件
   21-launchers\                             ← 本仓库 scripts\ 里的启动器

2) 双击 21-launchers\start-engine.bat
   看到 [ok] 与一行含 "content":"OK" = 成功（这一步是真发请求，不是探端口）

3) 客户端填：
   Base URL : http://127.0.0.1:8095/v1
   API Key  : 随意非空
   Model    : qwen3.8-27b
   超时     : ≥300 秒

4) 双击 21-launchers\stop-engine.bat 关机
```

**判断服务是否活着，必须真发一条请求。** 只 `GET /v1/models` 返回 200 **不算数**——
本引擎的 worker 崩掉之后它照样返回 200（这是已知缺陷，见 [docs/07](docs/07-排错手册.md)）。

## 实测数据一览

**测试条件**：计数语料，1,000 token 输入 / 1,000 token 输出，`temperature 0`，设备池 4,032。

| 指标                     | 本机实测                     | 上游参考机（RTX 4080 SUPER） |
| ------------------------ | ---------------------------- | ---------------------------- |
| 解码                     | **72.2 token/s**             | 194.6 token/s                |
| 预填                     | **653.8 token/s**            | ≈1,970 token/s               |
| TTFT（1,133 token 提示） | **1,733 ms**                 | 578 ms                       |
| 整轮总耗时               | **15.6 s**                   | —                            |
| MTP 接受                 | **779/879 = 88.6%**          | —                            |
| 第二轮命中率             | **99.0%**（TTFT **254 ms**） | —                            |
| 引擎启动                 | **3.3 ~ 3.5 s**              | —                            |

> 上游参考机的数字**不能当成本机预期**——多篇上游文档自己就标着"换机器请重跑，别照用数字"。
> 这也是本仓库存在的理由之一：**给出同一套判据下的本机真实读数**。

## 这套方案的适用边界（重要，先读再动手）

**适合：**

- 单张 **8 ~ 12 GB** NVIDIA 卡（sm_89），想跑 **长上下文 + 离线** 的大模型
- 纯文本：对话、长材料问答、代码片段工作
- **单用户、单路**：同一时刻一个请求

**不适合：**

- **并发服务多人**——引擎是单路语义，`--max-concurrency > 1` 会被硬拒
- **多模态**——模型件无视觉塔（`HAS_VISION=NO` 已实测）
- **联网/最新知识**——完全离线，知识停在训练时
- **依赖工具调用（function calling）的 agent 循环**——引擎支持但上游有已知缺陷，
  且 agent 客户端附带的超大提示词会直接把本地模型压垮（见 [docs/09](docs/09-第三方客户端接入.md)）
- **想省显存就把池调小**——上游明文"没测过、别压"

**本方案最反直觉的一条结论：**

> 把设备 KV 池从 **4,032** 调到 **8,192**（以为"池大 = 能装更多 = 更好"）实测是**负优化**：
> 解码 **72.2 → 44.8/43.8/45.5 token/s（−38%）**，整轮耗时 **15.6 → 22~25 s（+50%）**，
> 冷启动 TTFT **1,733 → 2,486 ms**，而正确性与复用率毫无提升。
> **这个实验已回退**，先前的启动器已删除，结论留在 [docs/04](docs/04-8GB显存档位适配.md)。

## 目录结构

```text
<部署根目录>\
├── 10-engine\engine\       引擎与运行期 DLL（需自行获取，见 docs/03）
├── 20-model\models\        模型件（需自行获取，见 docs/03）
├── 21-launchers\           启动器：start-engine / stop-engine / healthcheck / 三个档位启动器
├── 30-scripts\             校验脚本：档位验收、清单校验、模型件检查
└── 40-docs\                文档与实测原始日志
```

> 启动器与脚本内部一律使用**相对路径**（`%~dp0..`），所以整个目录可以整体搬走，
> 只要保持上面这个层级关系。
