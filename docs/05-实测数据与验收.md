# 05 · 实测数据与验收

> 本篇是所有数字的出处。**每个数字都标明测试条件**——不同条件之间的数字**不可直接比较**。

---

## 1. 先约定：哪个读数才算数

| 读数                           | 是否权威      | 说明                                                                                |
| ------------------------------ | ------------- | ----------------------------------------------------------------------------------- |
| **`req#N done` 行**            | ✅ **权威**   | 单条请求的真实统计：prompt / output / cache / TTFT / total / prefill / decode / MTP |
| `throughput \| 5.0s \| ...` 行 | ❌ **瞬时值** | 每 5 秒打一次的滚动窗口，别当性能结论                                               |
| 客户端显示的耗时               | ⚠️ 参考       | 含网络与客户端自身开销                                                              |
| 引擎启动耗时                   | ✅ 权威       | `engine ready \| total 3.3s`                                                        |

一条真实的 autoritative 读数长这样：

```text
INFO  req#1 done | openai-chat | stop token | prompt 1,133 | output 1,000 | cache 0 (0.0%)
      | TTFT 1,733 ms | total 15.6 s | prefill 653.8 tok/s | decode 72.2 tok/s | mtp accepted 779/879 (88.6%)
```

| 整轮     | **15.6 s**          | —                            | —            |

> "换机器请重跑，别照用数字"。

## 4. 验收结果

### 4.1 端到端验收脚本 → `RESULT: PASS`

| 检查项                          | 结果                 |
| ------------------------------- | -------------------- |
| 超池告警**负控**（池装得下时）  | 告警 **0** 行 ✅     |
| 超池告警**正控**（超池时）      | 告警 **≥1** 行 ✅    |

| 末尾针                          | **2/2** ✅           |
| 不变量违规                      | **0** 行（所有臂）✅ |

> 正控与负控**成对成立**才算通过——只测一边等于没测。

### 4.2 包完整性

```text
lines : 18
ok=18  mismatch=0  missing=0  unparsed=0
```

### 4.3 模型件自检

```text
MODELCHECK_VERDICT=PASS · LENGTH_MATCH=YES · COMPONENTS=mtp,text
HAS_DFLASH2=NO · HAS_VISION=NO · SPEC_CHOICES=mtp
RECOMMENDED_ARGV=--spec mtp --draft-tokens 4
```

### 4.4 ⚠️ 一条"结构性假红"，别被它骗了

上游的"引擎与卡匹配"自检，默认判据是 **`total_gib ≥ 8`**。而本机 `nvidia-smi` 报 **8,188 MiB**，
换算成 GiB 是 **7.996** ⇒ 默认判据下报 **FAIL**。

这是**结构性假红**（阈值边界问题），不是卡不匹配：

| 调用方式               | 结果                         |
| ---------------------- | ---------------------------- |
| 默认                   | `HWCARD_VERDICT=FAIL`        |
| 加 `-MinimumVramGiB 7` | **`HWCARD_VERDICT=PASS`** ✅ |

## 5. 复用（本方案的核心能力）

**测试**：同一会话第二轮，prompt 从 4,049 增至 4,104 token。

| 指标     | 第一轮       | 第二轮            |
| -------- | ------------ | ----------------- |
| prompt   | 4,049        | 4,104             |
| 命中缓存 | 0            | **4,061 = 99.0%** |
| TTFT     | **6,272 ms** | **254 ms**        |
| 结论     | 冷预填       | **复用生效**      |

另一次测得的复用读数：`cache 4,523 (99.6%, private endpoint)`，TTFT **223 ms**。

日志里的三条**自证行**（每次验收都该看到）：

```text
[ninfer] reuse host-backed: on
kvmem_score: SELECT label=text_prefill_chunk n_blocks=... kept=... scored_kept=...
[ninfer] adopt host-backed: frontier=4061 need=64 usable=63 host_backed=9
```

> `adopt host-backed` 这一行**不是**复用证据（它是无条件打印的）；
> 真正能证明复用生效的是 `cache` 百分比与 TTFT 的下降。

## 6. 【负结果】设备池 4,032 → 8,192

**测试条件**：计数语料 1,000/1,000，三次复测。

| 指标    | 池 4,032     | 池 8,192             | 变化     |
| ------- | ------------ | -------------------- | -------- |
| 解码    | **72.2**     | 44.8 / 43.8 / 45.5   | **−38%** |
| 整轮    | **15.6 s**   | 24.8 / 23.8 / 22.2 s | **+50%** |
| 冷 TTFT | **1,733 ms** | 2,486 ms             | **+43%** |
| 正确性  | 通过         | 通过                 | 无差异   |
| 复用    | 99.6%        | 99.6%                | 无差异   |

**处置**：回退到 4,032。实验用启动器已删除。
分析与"为什么与上游文档相反"见 [04 · §3](04-8GB显存档位适配.md)。

## 7. 压力与边界实测

| 场景                                 | 实测                                              | 说明                                 |
| ------------------------------------ | ------------------------------------------------- | ------------------------------------ |
| 4,049 token 提示（**超池**）         | TTFT **6,272 ms**，prefill 410~645 tok/s          | 触发超池告警，但中段针仍答对         |
| 58,941 token 提示（**14.6 倍超池**） | 预填 **98.4 s**，期间**零输出**，最后被客户端断开 | 这是"agent 客户端塞大壳子"的典型现场 |
| 4,104 token 第二轮                   | TTFT **254 ms**                                   | 复用生效                             |
| 短请求（127 token）                  | **678 ms** 答完                                   | 日常对话的正常水平                   |

## 10. 怎么自己复现这套验收

```powershell
# 1) 起引擎（自带检查 + 真请求验证）
.\21-launchers\start-engine.bat

# 2) 能力探针：问 7*5 应得 35，追加一轮问 +2 应得 37

# 3) 端到端验收
powershell -File .\30-scripts\verify-arch-engine-8g.ps1 -Port 8095 -MaxContext 65536 `
  -HostKvMib 4096 -KvDtype k8v4 -SmallPool 2048 -BigPool 8192 -Filler 400
#    期望末行 RESULT: PASS

# 4) 包完整性
powershell -File .\30-scripts\verify-kit-manifest.ps1 -Kit <部署根目录>
#    期望 ok=N  mismatch=0  missing=0

# 5) 收尾
.\21-launchers\stop-engine.bat
```
