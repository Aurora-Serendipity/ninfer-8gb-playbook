# 07 · 排错手册

> **出问题先翻这篇。** 结构：判活 → 症状速查 → 日志读法 → 启动失败逐项 → 已知缺陷与绕法 → 怎么报告问题。
>
> 三条铁律先记住：
>
> 1. **`/v1/models` 返回 200 不算活着**（上游账本 B02：worker 崩了它照样 200）——必须真发请求。
> 2. **网关 8081 不实现 `GET /v1/models`（501）**——判活打引擎 8080。
> 3. **任何"看起来正常"都不能当证据**——超池会静默答错、网关会静默丢材料。

---

## 1. 第一步永远是判活

### 1.1 三条可复制的命令

```powershell
# 1) 最省事：一键体检（真发一条请求，判据是末行 [PASS]）
powershell -NoProfile -ExecutionPolicy Bypass -File .\21-launchers\healthcheck.ps1

# 2) 手工发一条（把回答原样贴出来看）
$body = '{"model":"j27b","messages":[{"role":"user","content":"Reply with exactly: OK"}],"temperature":0,"max_tokens":8}'
Invoke-RestMethod -Uri 'http://127.0.0.1:8080/v1/chat/completions' -Method Post -ContentType 'application/json' -Body $body

# 3) 看启动器当前档位与进程状态
Invoke-RestMethod -Uri 'http://127.0.0.1:8720/api/state'
```

### 1.2 能说明什么、不能说明什么

| 检查                            | 能说明               | 不能说明                   |
| ------------------------------- | -------------------- | -------------------------- |
| `GET /v1/models` = 200          | 引擎 HTTP 服务在     | **模型还能不能答**（B02）  |
| TCP 端口 8080/8081 在听         | 进程活着、端口没被占 | 引擎是否卡死/worker 是否崩 |
| `healthcheck.ps1` 末行 `[PASS]` | **真请求答出来了**   | 长题面/长输出是否正常      |
| GPU 显存被占                    | 引擎已加载权重       | 请求能不能过               |

### 1.3 顺手确认另外两件事

- **当前档位**：`http://127.0.0.1:8720/api/state` 的 `selected_profile` 应是 `8g-daily` 或 `8g-longctx`。
- **显存**：`nvidia-smi --query-gpu=memory.used --format=csv,noheader,nounits` ≤ **7,488 MiB** 红线；
  空闲基线 + 引擎 ≈7 GB。

## 2. 症状 → 处置 速查表

| 症状                                                           | 最可能原因                                                    | 处置                                                                                             |
| -------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 启动脚本报 `REDLINE_EXCEEDED`，引擎没起                        | 显存被别的进程占 / 档位贴线                                   | 关占卡程序（浏览器硬件加速/Overlay/QQ/录屏/其它 AI）；见 [04 §7](04-8GB显存档位适配.md) 退档阶梯 |
| 引擎日志 `runtime reservation requires … but only … available` | 缺 `--no-cuda-graph`                                          | 确认命令行有 `--no-cuda-graph`（两档 profile 的 `extra_argv`）                                   |
| 日志 `[ring] host_kv_arena is null … run dense`                | 缺 `NINFER_HOST_PAGEABLE=1`                                   | profiles 的 env 补上（[04 §5](04-8GB显存档位适配.md)）                                           |
| 启动报 `GATEWAY_TIMEOUT` 但引擎已就绪                          | 网关日志块缓冲（L-03）                                        | 网关以 `-u` 启动（launcher 补丁）；或从控制台先手动起网关                                        |
| 短请求返回空正文 / `content=""`                                | 思考档没关                                                    | `--default-reasoning-effort none`；或客户端带 `thinking_budget ≥1024`                            |
| 连续长请求后 HTTP **429**                                      | **B33**（上下文缓存排不下）                                   | **停/启引擎**（`stop-daily.bat` → `start-daily.bat`）                                            |
| 输出写一半停了（`finish_reason=length`）                       | **B37**（客户端没给 `max_tokens`）/ **B35**（题面+输出 > 池） | 客户端显式给 `max_tokens`；保证题面 + 输出 ≤ 池                                                  |
| 答非所问 / 中段事实丢了                                        | 超池（日志 `prompt exceeds the resident Device KV pool`）     | 换长档 / 分片；或缩短题面到池内                                                                  |
| 长材料问答时模型说"没看到材料"                                 | 网关 **L1 丢弃**了超大单条历史消息                            | 把长材料放到**最后一条 user 消息**；或用长档 / 分片                                              |
| 客户端拉模型列表 501 / 报错                                    | 网关不实现 `GET /v1/models`                                   | 用 8080 判活；模型名固定 `j27b`                                                                  |
| 请求 404（模型不存在）                                         | 模型 id 写错（如 `j27b-long`）                                | **只能用 `j27b`**；两档靠两个 provider/预算区分                                                  |
| 请求 400 `context_length_exceeded`                             | 题面超过 `--max-context`                                      | 换长档或分段；这不是池问题                                                                       |
| 中文变乱码（`æ»å±æ`）                                          | **B36**：响应头缺 `charset=utf-8`                             | 客户端按 UTF-8 解码（PowerShell 5.1 会踩）                                                       |
| 长档很慢                                                       | 长档无 MTP（20 tok/s），48k 题面 TTFT ≈79 s                   | 正常代价；要快换日常档                                                                           |
| 同一时刻第二个请求卡住                                         | 单路引擎排队                                                  | 等前一个结束；不要并发                                                                           |
| 端口 8080/8081 被占                                            | 其它程序 / 上次残留引擎                                       | 控制台点停止；或找占端口的进程处理                                                               |
| `FOREIGN_ENGINE`：另一个 infer-serve.exe 在跑                  | 手工启过 / 旧实例残留                                         | 启动器**不会**杀别人的进程；自行结束那个进程再启动                                               |
| 停机后显存没释放                                               | 引擎窗口没关 / 非 launcher 启的进程                           | 从控制台 8720 停止；或任务管理器结束 `infer-serve.exe`                                           |
| `python.exe` 找不到                                            | 包解压不完整                                                  | 重新解压分发包（`runtime\python\` 应在）                                                         |

## 3. 日志怎么读

日志位置：`10-engine\logs\engine-*.log`、`10-engine\logs\gateway-*.log`；控制台 8720 也能在线看。

### 3.1 正常关键行（正常就该有）

```text
engine ready | bonsai2-27b | total 3.3s | weights 5.94 GiB | …
capacity | KV 12,800 tokens, rk2v4-e8, explicit | pages 200/2,048 | runtime 675.6 MiB | free 340.0 MiB
host KV pinned | 3.25 GiB
context cache | host 8 states, 3.25 GiB KV
[ring] budgets … sum==pool: yes
[spec] backend=mtp draft_tokens=4 attention_window=8 ngram=15
req#1 started | … | max output 4096 | thinking off | tools 0
req#1 done | … | prompt 1,121 | output 804 | cache 0 (0.0%) | TTFT 1,733 ms | total 14.4 s | decode 63.3 tok/s …
```

### 3.2 危险行（要处理）

| 行                                                        | 含义                             | 处置                                      |
| --------------------------------------------------------- | -------------------------------- | ----------------------------------------- |
| `prompt exceeds the resident Device KV pool … unverified` | **超池**，答案不可信             | 换长档 / 缩短 / 分片                      |
| `Paged KV pool has no free page for host-restore`         | **B33** 的 429 现场              | 重启引擎                                  |
| `[ring] host_kv_arena is null … run dense`                | 主机层失效                       | 补 `NINFER_HOST_PAGEABLE=1` 重启          |
| `active KV snapshot page ownership is not ordered`        | 环模式下共享前缀快照崩（B01 类） | 确认 `--max-shared-prefixes 0` 在命令行里 |
| `worker crash` / `FATAL` / `ERROR`                        | 引擎级故障                       | 先按 §4 逐项排查，再留日志报告            |

### 3.3 吓人但无害的行（不用管）

- `prefill …` / `ring retrieve …` / `kvmem_score: SELECT …` / `mask hidden …` / `demote-other …`：
  长题面每个 1,024 token 块打一遍，刷屏正常。
- `queue N ms`：单路排队，不是错误。
- `publish host-backed` / `adopt host-backed`：复用链路的常规行为。

### 3.4 读日志的三条纪律

1. **以 `req#N` 为单位**：把 `started` 与 `done` 两行对上号，才是一条完整请求。
2. **`throughput | …` 是瞬时值**，别当性能结论；权威是 `req#N done`。
3. **看 `thinking off` 与 `max output`**：这两项不对，说明档位/参数没按方案来。

## 4. 启动失败逐项（按错误码）

启动器的预检（preflight）与启动错误都有**错误码**，直接对表：

| 错误码                    | 含义                                                          | 处置                                                           |
| ------------------------- | ------------------------------------------------------------- | -------------------------------------------------------------- |
| `RUNTIME_MISSING`         | `runtime\` 目录缺失                                           | 重新解压分发包（DLL 必须整组在）                               |
| `GATEWAY_MISSING`         | `gateway\chat_gateway.py` 缺失                                | 恢复网关文件                                                   |
| `NO_GPU`                  | `nvidia-smi` 失败或无 GPU                                     | 重装/修复驱动；确认不是远程桌面断开导致 GPU 不可见             |
| `UNSUPPORTED_COMPUTE_CAP` | 算力不在 8.6/8.7/8.9/12.0                                     | 本方案不支持该卡（如 A100 8.0、13.0）                          |
| `REDLINE_EXCEEDED`        | 档位预算超红线，拒绝启动                                      | 关占卡程序；按 [04 §7](04-8GB显存档位适配.md) 退档             |
| `MODEL_MISSING`           | `10-engine\model\` 下没有 `*.ninfer`                          | 放模型/建硬链接                                                |
| `PORT_BUSY`               | 8080/8081 被占                                                | 控制台停止旧实例；找出占端口进程                               |
| `FOREIGN_ENGINE`          | 另一个 `infer-serve.exe` 在跑                                 | 启动器不杀别人进程；手动结束后再起                             |
| `ENGINE_EXIT`             | 引擎进程提前退出                                              | 看 `logs\engine-*.log` 尾部；常见是 reservation 或模型件不匹配 |
| `GATEWAY_TIMEOUT`         | 网关 25 s 内没就绪                                            | 见 L-03（`-u`）；或看 `logs\gateway-*.log`                     |
| `POOL_MISMATCH`           | 网关自称 pool ≠ 引擎 `--kv-capacity`                          | profile/launcher 改坏了；恢复补丁或重打                        |
| `HARD_ASSERT_FAILED`      | 命令行硬断言失败（`--max-shared-prefixes` / `--kv-capacity`） | 不要把受保护开关写进 `extra_argv`；检查 profile                |
| `CONFIG_VIOLATION`        | `extra_argv` 设置了受保护开关                                 | 删掉；受保护开关由 launcher 管                                 |

## 5. 已知缺陷与绕法（上游未修项）

> 缺陷编号沿用上游账本，便于对照。本表只写**本机实测到/会影响使用**的几条。

| 编号    | 症状                                                         | 本方案绕法                                                                                     |
| ------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| **B01** | 超池请求可能崩溃 / 容量拒绝 / 重发后不可用                   | 保留 `--max-shared-prefixes 0`；客户端 `max_tokens` 不超过池；题面 ≤ 池                        |
| **B02** | worker 崩了 `/v1/models` 仍 200（健康检查骗人）              | **一律真发请求判活**（一键脚本/体检脚本已内置）                                                |
| **B17** | 工具调用（function calling）不可靠，agent 循环易退化         | 本地小模型别跑大量工具的 agent 循环；DSH 里关掉实验性工具包（见 [09](09-第三方客户端接入.md)） |
| **B33** | 连续长请求后 HTTP 429（`no free page for host-restore`）     | **停/启引擎**；避免连续轰炸长请求                                                              |
| **B35** | 题面 + 输出 > 池 ⇒ 输出被静默截断（`finish_reason=length`）  | **题面 + 输出 ≤ 池**；本方案已按此设两档默认值与网关 headroom                                  |
| **B36** | 响应头缺 `charset=utf-8` ⇒ 部分客户端中文乱码                | 客户端强制 UTF-8；PowerShell 5.1 下注意输出编码                                                |
| **B37** | 客户端不显式给 `max_tokens` ⇒ 服务端默认上限静默截断         | **客户端显式给**；本方案默认已抬到 4,096 / 8,192，但仍建议显式                                 |
| 网关 L1 | 超池时**整条丢弃**超大历史消息（实测 17,701 est → 材料没了） | 长材料放最后一条 user 消息；或长档 / 分片                                                      |

## 6. 接第三方 agent 客户端时的故障

**机制一句话**：agent 客户端会把**自己的一整套系统提示词 + 工具 schema**（动辄几千到几万 token）
塞进每次请求；本地小模型的池只有 12,800/51,200，超了就走检索/让位，表现就是**慢、答不准、空回答**。

**判据**：看引擎日志里同一个 `req#N` 的 `started` / `done` 两行——

- `prompt` 是否接近/超过池（日常 12,800 / 长档 51,200）；
- `max output` 是否与客户端要求一致；
- `thinking off` 是否为真。

**处置**（按优先级）：

1. 客户端里**只保留必需工具**（DSH 的本地模式 preset 已把工具面压到 5 个：pwsh + read/write/edit/read_image）。
2. 关掉附加的实验性工具包（DSH：GUI → Plugins → `dsh-experimental-agent-team-profile` 关闭，热重载）。
3. 会话太长就**新开会话**（别把整段历史拖进本地模型）。
4. 需要贴长材料时，放最后一条 user 消息，别塞进 system/工具结果。

完整故障还原与 DSH 定制方案见 [09 · 第三方客户端接入](09-第三方客户端接入.md)。

## 7. 报告问题时该带什么

### 7.1 必带清单

1. 卡型号、驱动版本、显存（`nvidia-smi` 全输出）。
2. 档位（`/api/state` 的 `selected_profile`）与**完整启动命令行**（`/api/state` 或日志里有）。
3. 引擎日志尾部 80 行 + 网关日志尾部 80 行（`10-engine\logs\`）。
4. 出问题的**请求原文**（含 `max_tokens`、题面 token 数）与**响应原文**（含 `finish_reason`、`usage`）。
5. 包/模型校验结果（`verify-engine-package.ps1` 的 SUMMARY、`check-model.ps1` 的 VERDICT）。

### 7.2 口径提醒（否则报告会被打回）

- 报速度必须带**测试条件**（语料、输入/输出长度、温度、池大小）。
- 报显存必须说明是**峰值采样**还是空闲值。
- 报"答错"必须说明**题面 token 数 vs 池**，并附 `prompt exceeds` 告警是否存在。

### 7.3 最小可复制报告模板

```text
[环境] RTX 4060 Laptop 8GB / 驱动 616.64 / 32GB RAM
[档位] 8g-daily（池 12,800 / ctx 131,072 / out 4,096 / MTP4）
[命令] 21-launchers\start-daily.bat
[现象] 第 3 条长请求后全部 429；日志尾部：
        … Paged KV pool has no free page for host-restore …
[已试] stop-daily.bat → start-daily.bat（恢复）；未改任何参数
[校验] verify-engine-package: ok=66 mismatch=0 missing=0 deviated=2 RESULT: PASS
        check-model: MODELCHECK_VERDICT=OK
```
