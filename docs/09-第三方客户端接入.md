# 09 · 第三方客户端接入（agent 客户端的坑）

> 本篇来自一次**真实故障的完整还原**：把本地模型接进一个 agent 客户端后，
> 用户只说了一句「你好」，等了 **98 秒**零输出——最后请求被客户端断开。
>
> 故障已定位并修好。这一篇把**原理、通用结论、以及踩过的技术坑**全部写下来。

---

## 1. 故障现场（实测数据，不是推断）

| 项                       | 实测值                                                       |
| ------------------------ | ------------------------------------------------------------ |
| 用户输入                 | 「你好」（几个 token）                                       |
| **引擎实际收到的提示词** | **58,941 token（921 页）**                                   |
| 其中工具定义             | **`tools 176`**，工具 JSON 本身 **189,876 字节 ≈ 47k token** |
| 其中系统提示词           | **14,297 字节**                                              |
| 客户端申请的输出额度     | **8,301 token**                                              |
| 设备池                   | 4,032 token ⇒ **超池 14.6 倍**                               |
| 引擎预填耗时             | **98.4 秒**，期间**零输出**                                  |
| 结局                     | `cancelled` · `output 0` · `HTTP 499 client disconnected`    |

**一句话**：你的"你好"被 agent 客户端的**工具定义 + 系统提示词**包成了一个 5.9 万 token 的请求。
本地模型是 72 token/秒、单路、设备池只有 4,032，**扛不动这种壳子**。

---

## 2. 176 个工具是从哪来的

从会话记录的 `request/header` 里**逐个数出来**的：

| 来源                       | 个数    | 明细                                                                                                        |
| -------------------------- | ------- | ----------------------------------------------------------------------------------------------------------- |
| **MCP 服务器**（全局挂载） | **135** | chrome-devtools 30 · context7 2 · firecrawl 29 · gitee 25 · github 49                                       |
| 内置 `standard` 模式自带   | **27**  | pwsh · read/write/edit/read_image · glob/grep · job×3 · skill · goal×3 · subagent×2 …                       |
| 宿主层**可选实验包**       | **14**  | schedule×4 · mcp 资源×3 · list_subagent_models · load_workspace_dependencies · spawn_teammate · team_task×4 |
| **合计**                   | **176** |                                                                                                             |

---

## 3. 两个决定性机制（**决定了"光新建一个轻量模式不够用"**）

这是本次故障最反直觉的部分，也是最值得抄走的知识：

### 3.1 模式（preset）只能"加"，不能"减"

> 工具可见面 = **全局层 + 作用域链上所有祖先层的并集**。

所以新建一个"只声明 2 个工具"的轻量模式，**并不会**让 MCP 和宿主层的工具消失——
它们注册在更上层，照样继承下来。**"换成极简模式就好了"是一个陷阱。**

### 3.2 有些工具连"按 agent 屏蔽"都删不掉

屏蔽 API（`ctx.tools.restrict()`）只过滤**继承来的**工具，
**不过滤 agent 自己那一层注册的工具**。

而某些插件（队友包 9 个、日程包 4 个）是把工具注册进 **agent 自己的作用域**的。
⇒ **这 13 个工具只能从"可选实验包"层面关掉**，屏蔽 API 对它们永远无效。

> **通用推论**：诊断任何"换模式后工具/提示词没降下来"的问题，先问一句——
> **"这东西注册在哪个作用域？"**（全局层 / 模式层 / **agent 自己的层**），再决定能不能屏蔽。

---

## 4. agent 客户端的三个"隐性成本"

| 成本                      | 说明                                              | 本次实测                                           |
| ------------------------- | ------------------------------------------------- | -------------------------------------------------- |
| **工具定义**              | 每个工具的 schema 都要进提示词                    | 176 个 ⇒ **189,876 字节 ≈ 47k token**              |
| **系统提示词 + 技能目录** | 描述"你能做什么"的长文本                          | 另加 **14,297 字节**                               |
| **输出额度自动推导**      | 客户端常按 `上下文窗口 − 提示词` 自动申请输出额度 | 被推到 **8,301** ⇒ 超过设备池 ⇒ **踩中崩引擎红线** |

> ⚠️ **第三条尤其危险**：客户端并不知道你的设备池只有 4,032。
> 更糟的是，若客户端**不声明**输出上限，适配器的兜底值可能是 **32,768**（= 设备池的 8 倍）——
> 这正是上游账本里"**超池 + 大输出额度 ⇒ worker 崩溃 ⇒ 此后全 503**"那条红线的**必崩配方**。
> **必须把输出额度显式写死为 ≤ 设备池（本方案：2,048）。**

---

## 5. 一眼判断一个请求会不会卡

**只看引擎日志里 `req#N started` 那一行的两个数字**：

```text
INFO  req#3 started | openai-chat stream | 5 messages | max output 8,301 | thinking off | tools 176
                                                                                        ^^^^^^^^^^^  ^^^^^^^^^
                                                                                          prompt 数    工具数
```

| prompt       | tools | 预期                                                  |
| ------------ | ----- | ----------------------------------------------------- |
| 几百 ~ 几千  | ≤ 10  | ✅ 顺畅（实测一条 127 token 的请求 **678 毫秒**答完） |
| 1 万 ~ 3 万  | 任意  | ⚠️ 等 20~60 秒                                        |
| **5 万以上** | 任意  | ❌ 等 1~2 分钟，客户端多半先超时                      |

**定制模式的验收标准就是这两个数字**：`tools ≤ 8` 且 `prompt ≤ 3,000`。

## 6. 解决方案与实测结果

### 6.1 定制后的组成

| 组成             | 内容                                                                      |
| ---------------- | ------------------------------------------------------------------------- |
| 人设             | 305 字（≈185 token），`complete: true` + `includeRuntimeContext: false`   |
| **工具掩码插件** | 屏蔽 **139 个继承来的工具** + 清空 **3 段宿主提示词**（合计 10,195 字节） |
| 工具 1           | `pwsh`                                                                    |
| 工具 2–5         | `read` / `write` / `edit` / `read_image`                                  |
| 上下文管理       | 自动压缩 + 工具结果裁剪（0 个工具）                                       |

其中工具掩码插件**只在轻量模式的作用域内生效**，不影响云端会话。

### 6.2 实测前后对照

| 指标           | 改之前                                | 改之后（15:47）           | 复验（17:23）             |
| -------------- | ------------------------------------- | ------------------------- | ------------------------- |
| 输出额度       | 未声明 ⇒ 发 **32,768**                | **2,048**                 | **2,048**                 |
| 工具数         | **18**                                | **5**                     | **5**                     |
| 工具 JSON 字节 | 16,501                                | **6,162**                 | —                         |
| 引擎 prompt    | **5,004**（**超池，有警告**）         | **2,076**（池内，无警告） | **2,140**（池内，无警告） |
| TTFT           | 98 秒零输出（更早的 `standard` 模式） | **3.5 s**                 | **3.7 s**                 |
| 结局           | `HTTP 499` · `output 0`               | 正常出字                  | `stop token`              |

> 15:47 → 17:23 的 2,076 → 2,140 的 +64 token，是因为**会话历史从 6 条涨到 10 条**，
> **不是回归**。这套配置在"开关反复切换 + 重启"之后依然稳定。

**最终验收**：`tools 5` ✅ · `max output 2,048` ≤ 池 ✅ · `prompt 2,140` ≤ 3,000 ✅ · 无超池警告 ✅

### 6.3 ⚠️ 唯一的全局代价（务必知道）

本次定制**只动了一个全局开关**：关掉两个**可选实验包**（多智能体/队友包、日程包）。
关掉后，**云端会话**会少 10 个工具：

| 少了                                                 | 个数                                      |
| ---------------------------------------------------- | ----------------------------------------- |
| `spawn_teammate`、`team_task_create/list/get/update` | 5                                         |
| `wait_agent`                                         | 1                                         |
| `schedule_create/list/delete/update`                 | 4（**外加"当前日期时间"**，它随日程包走） |

**恢复方式：客户端 GUI 的插件页把两个包点开即可**（热重载、两步、**不需要改任何配置文件**）。
实测恢复后云端工具数回到 **179**、工具 JSON **逐字节相同（194,006 B）**。

**一句话记法**：这两个包 = "**云端重装备**"开关。开着是完整云端，关着本地模型才能喘气。
**别在同一个时段既跑云端多智能体又跑本地模型。**

## 7. 六个技术坑（做过的人才知道）

| #   | 坑                                                          | 现象 / 处置                                                                                             |
| --- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 1   | **嵌套在模式里的本地插件，路径必须写成完整 `file:///` URL** | 否则：**模式能选中、补丁校验通过、插件的 `apply()` 却永远不执行**——极具迷惑性。非相对路径会被当成协议名 |
| 2   | **输出上限必须显式写死**                                    | 不写时适配器兜底可能发 **32,768** = 必崩配方（见 §4）                                                   |
| 3   | **模式作用域"只加不减"**                                    | 见 §3。先问"注册在哪个作用域"                                                                           |
| 4   | **不改客户端也能验证发出去的内容**                          | 会话记录里的 `request/header` **就是发给引擎的原文**（工具清单、输出上限）。多帧压缩的日志要逐帧解      |
| 5   | **只读检查运行中的宿主配置**                                | 用宿主提供的检查接口列出"当前 agent 实际可见的工具"，改完掩码后复核最快                                 |
| 6   | **别把本地模型设成客户端的默认模型**                        | 云端模型上下文大 15 倍，同一个壳子饭量完全不同                                                          |

---

## 8. 通用铁律（不限于某个客户端）

1. **不要把本地模型设成 agent 客户端的默认模型。**
2. **换轻量模式之前，先确认全局插件/MCP 会不会继续注入工具**（"只加不减"）。
3. **输出额度必须显式封顶**，不能交给客户端自动推导。
4. **验收只看引擎日志的两个数字**（`tools` / `prompt`），不看界面是否"连上了"。
5. **尽量新开会话**：把云端的长会话切成轻量模式 = 把几万 token 历史塞进 4k 池，又慢又不可信。

## 9. 客户端通用配置（任何 OpenAI 兼容客户端）

| 设置项       | 值                                       |
| ------------ | ---------------------------------------- |
| Base URL     | `http://127.0.0.1:8095/v1`               |
| API Key      | 任意非空字符串（服务端 `auth disabled`） |
| Model        | `qwen3.8-27b`                            |
| 超时         | **≥ 300 秒**                             |
| 流式输出     | 建议开                                   |
| `max_tokens` | **≤ 2,048**（硬上限 4,032）              |

> ⚠️ 服务**没有鉴权**，只监听 `127.0.0.1`。**不要**改成 `0.0.0.0`，也不要暴露到局域网。

---

## 10. 一句话总结

> **本地模型不是"小号的云端模型"。给它套 agent 壳子之前，先算两笔账：
> 壳子有多少工具、要多少 token。这两笔账超了，等多久都是白等。
> 而且——壳子挂在全局的那些工具，换个"轻量模式"是甩不掉的，得从挂载它的那一层关。**
