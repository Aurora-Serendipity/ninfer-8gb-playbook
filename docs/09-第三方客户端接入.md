# 09 · 第三方客户端接入（OpenAI 兼容 / DSH / agent 客户端）

> 本篇讲三件事：**怎么把 v2 引擎接进任意 OpenAI 兼容客户端**、**DSH 的两 provider 配置**、
> **接 agent 客户端时会踩什么坑（以及为什么本地小模型不适合重工具面）**。

---

## 1. 接口口径（先看这张表）

| 项                      | 值                                                                             |
| ----------------------- | ------------------------------------------------------------------------------ |
| 网关 baseURL（推荐）    | **`http://127.0.0.1:8081/v1`**                                                 |
| 引擎直连 baseURL        | `http://127.0.0.1:8080/v1`                                                     |
| 模型 id                 | **`j27b`**（引擎只认这个；写 `j27b-long` 等 → 404）                            |
| API Key                 | 随便非空（服务端 auth disabled）                                               |
| 接口                    | `/v1/chat/completions`（含 SSE 流式）、`/v1/models`；`tools`/`tool_calls` 透传 |
| 网关的 `GET /v1/models` | **501（不实现）**——判活打引擎 8080                                             |
| 并发                    | **1（单路）**                                                                  |
| 鉴权                    | **无**——只监听 `127.0.0.1`，不要改成 `0.0.0.0`                                 |
| 响应头 charset          | 上游 B36：不带 `charset=utf-8` ⇒ 客户端要按 UTF-8 解码                         |

**为什么推荐走网关（8081）**：题面 + 输出超过池时，网关会先做让位（裁历史 / 分段摘要 / 压缩 / 诚实拒答），
避免引擎静默答错；直连 8080 则风险自负。**代价**：网关让位是有损的（见 §5）。

## 2. 最小可跑示例

```powershell
# PowerShell：真发一条请求
$body = @{
  model = 'j27b'
  messages = @(@{ role = 'user'; content = 'Reply with exactly: OK' })
  temperature = 0
  max_tokens = 16
} | ConvertTo-Json -Depth 8 -Compress
Invoke-RestMethod -Uri 'http://127.0.0.1:8081/v1/chat/completions' `
  -Method Post -ContentType 'application/json; charset=utf-8' -Body $body
```

```bash
# curl（Git Bash / WSL）
curl -s http://127.0.0.1:8081/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"j27b","messages":[{"role":"user","content":"7*5=?"}],"temperature":0,"max_tokens":32}'
```

**判据**：返回 `choices[0].message.content` 有内容且 `finish_reason` 正常（`stop` 或 `length`）。

## 3. 客户端参数与约束

| 参数                          | 日常档                          | 长档                         | 说明                                                          |
| ----------------------------- | ------------------------------- | ---------------------------- | ------------------------------------------------------------- |
| `contextWindow`（客户端配置） | **10,240**                       | **42,496**                   | = 池 − 输出 − 512 slack；**这是客户端有效预算，不是逻辑窗口** |
| `maxTokens`（单次输出）       | **2,048**                       | **8,192**                    | 必须显式给（B37）                                             |
| 单条题面建议上限              | ≤ 10,240                         | ≤ 42,496                     | 超了先分段/分片                                               |
| 超时                          | ≥300 s                          | ≥600 s（8k 输出约 6~7 分钟） | 长档 48k 题面 TTFT 约 79 s                                    |
| 并发                          | 1                               | 1                            | 队列化                                                        |
| `temperature`                 | 0~0.3（代码/事实）、0.7（闲聊） | 同左                         | 默认 0.7                                                      |
| `stream`                      | 可选                            | 可选                         | SSE 只出正文（`thinking off`）                                |

> **档位与预算必须匹配**：日常档跑着时用长档预算（ctx 42496 / out 8192）是**错配**——
> 最坏情况题面 42k + 输出 8k 远超日常池 12,800，输出可能被静默截断。
> 两档分别对应两个客户端 provider（见 §4）。

## 4. DSH（DeepSeek Harness）接入

DSH 的「本地小模型模式」在 v2 迁移后是**两个 provider、同一个模型 id**（引擎不认不同 model id，
但客户端需要不同的预算表达）：

| provider（配置 id）   | 显示名                         | baseURL                    | 模型显示名   | contextWindow | maxTokens | 适用   |
| --------------------- | ------------------------------ | -------------------------- | ------------ | ------------: | --------: | ------ |
| `ninfer-local-deploy` | NInfer Local (Daily 8G)        | `http://127.0.0.1:8081/v1` | `j27b-daily` |    **10,240** | **2,048** | 日常档 |
| `ninfer-local-long`   | NInfer Local (Long-context 8G) | `http://127.0.0.1:8081/v1` | `j27b-long`  |    **42,496** | **8,192** | 长档   |

**模式（preset）**：`local-8g`，显示名 **「本地小模型模式（8G·KV 流式）」**；
人设已更新为 j27b 两档口径；工具面保持 **5 个**（pwsh + read/write/edit/read_image）。

**使用步骤**：

1. 先启动一个档（`21-launchers\start-daily.bat` 或 `start-long.bat`）。
2. **重启 DSH**（provider/preset 在宿主启动时装载；不重启不生效）。
3. **新开会话** → 选「本地小模型模式（8G·KV 流式）」→ 按当前档选 `j27b-daily` 或 `j27b-long`。
4. 验收：看引擎日志 `req#N started | … | max output 2048|8192 | thinking off | tools N`，
   `prompt ≤ 10240`（日常）/`≤ 42496`（长档）。
5. 用完 `stop-daily.bat` 释放显存。

**注意**：

- **不要开旧会话**：旧会话记录的是 v1 的模型/端口，v2 已没有。
- 实验包 `dsh-experimental-agent-team-profile` 建议关闭（会把工具面从 5 变多、prompt 变长；
  本地小模型多工具调用不可靠，上游 B17）。GUI → Plugins 页关闭，热重载。
- 掩码插件日志在 DSH 本地模式目录（可随时删，不影响功能）。

## 5. 接 agent 客户端时的三个"隐性成本"

agent 客户端（DSH / Cline / 各种 IDE 插件）不是"聊天框"：它每次请求都附带一大堆东西：

| 成本                | 是什么                                 | 对本地小模型的影响                                    |
| ------------------- | -------------------------------------- | ----------------------------------------------------- |
| **系统提示词**      | 客户端自己的行为规范（动辄几千 token） | 挤占池；日常档 10,240 预算很容易被吃掉一半             |
| **工具 schema**     | 每个工具的 JSON 描述都进 prompt        | 工具越多 prompt 越大；且小模型多工具调用不可靠（B17） |
| **历史/文件上下文** | 自动附加的对话历史、打开的文件         | 超过池 → 检索/让位 → 变慢、答不准、空回答             |

**实测过的失败形态**（v1 时代就踩过，v2 机制没变）：

- 请求 prompt 远超池 ⇒ 等待几十秒后**零输出**或空正文；
- 工具面巨大（几十上百个工具）⇒ 模型在工具调用上循环，答不出内容；
- 长历史被网关 L1 裁掉/丢弃 ⇒ 模型"没看到材料"。

**对策**（按优先级）：

1. **用厂商提供的本地模式/preset**（DSH 已有：5 工具、精简人设、压缩策略适配小模型）。
2. 关掉非必要实验包与插件。
3. 一次只开一个文件/一个小任务；会话长了就新开。
4. 需要长材料时：材料放**最后一条 user 消息**，并显式说明"只回答最后的问题"。

## 6. 其它客户端配置（通用）

任何 OpenAI 兼容客户端（Chatbox / Open WebUI / LM Studio 的"外部服务" / 自写脚本）：

```text
API 类型   : OpenAI Compatible
Base URL   : http://127.0.0.1:8081/v1
API Key    : local（随意非空）
Model      : j27b
Context    : 10240（日常档）/ 42496（长档）
Max Tokens : 2048（日常档）/ 8192（长档）
Timeout    : ≥300 s（长档 ≥600 s）
Temperature: 0.7（默认）或 0（确定性任务）
```

> 有的客户端会**自动推导** context/max_tokens（例如按模型名猜 32k）——**手动改掉**，
> 让它们 ≤ 上面的预算，否则会触发超池（不可信）或 B37 截断。

## 7. 从旧 v1 客户端迁移（清单）

如果你之前接过 v1 的那套（2026-10-07 前），按这张表改：

| 项         | v1                                                      | v2                                                          |
| ---------- | ------------------------------------------------------- | ----------------------------------------------------------- |
| baseURL    | v1 的旧端口与旧路径（v1 归档说明，见 `git tag v1.0.1`） | `http://127.0.0.1:8081/v1`（网关）或 `8080`（引擎）         |
| model      | v1 的模型名                                             | **`j27b`**                                                  |
| 上下文预算 | v1 的窗口口径                                           | 日常 **10,240** / 长档 **42,496**（客户端有效预算）          |
| 输出上限   | v1 的默认值                                             | 显式 `max_tokens`：2,048 / 8,192                            |
| 会话       | 旧会话里记着 v1 模型/端口                               | **新开会话**（旧会话不可用）                                |
| 启动方式   | v1 的独立启动器                                         | `21-launchers\start-daily.bat` / `start-long.bat`           |
| 判活       | —                                                       | 真发请求（`healthcheck.bat`）；网关 `GET /v1/models` 是 501 |

---

## 8. 一句话总结

> **接本地模型不是"填个 baseURL"就完事：客户端的系统提示词、工具面、历史都在花池子的钱。
> 用精简模式、给显式 `max_tokens`、把预算和当前档对齐，它才稳定。**
