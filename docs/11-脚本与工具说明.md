# 11 · 脚本与工具说明

这套部署共 9 个脚本：3 个日常一键脚本、3 个启动器、3 个校验脚本。本文逐个说明**怎么用、它实际做了什么、看什么输出算成功**，最后统一交代脚本的通用约定。

> **口径**：只写脚本里真实存在的行为，参数名、取值、屏幕输出全部照抄脚本原文；文中的实测数字都来自启动器注释里记载的、在这台 8 GB 显存机器上复验过的结果。命令按部署后的目录树书写：一键脚本与启动器在 `21-launchers\`，校验脚本在 `30-scripts\`；路径一律用相对说法 —— 启动器内部用 `%~dp0` 定位，整套目录可以整体搬走。

## 脚本总览

| 脚本                           | 一句话用途                                                  | 什么时候用                               |
| ------------------------------ | ----------------------------------------------------------- | ---------------------------------------- |
| `start-engine.bat` ★           | 检查环境 → 另开窗口拉起推荐启动器 → 探端口 → 真发一条请求   | 每天开工，双击                           |
| `stop-engine.bat` ★            | 先显示进程，确认后结束引擎，再复查进程/端口/显存            | 收工、换参数重启前，双击                 |
| `healthcheck.bat`              | 打一次 `/v1/models` 状态码 + 发一条**真请求**，证明服务活着 | 怀疑"卡住了"时另开窗口跑                 |
| `start-ptq1-mtp-8g-safety.bat` | 基准启动器 + 两个 B01 防崩开关（**日常推荐**）              | 日常启动；`start-engine.bat` 自动调它    |
| `start-ptq1-mtp-8g.bat`        | 8 GB 适配的实测基准启动器（未改动）                         | 对照实验、复现基准数据                   |
| `start-ptq1-mtp-verbatim.bat`  | 原厂 argv 逐字保留，仅改了路径                              | 只做"原厂 vs 适配"对照，**本机跑不起来** |

| `verify-kit-manifest.ps1`      | 按字节校验套件的 `SHA256SUMS.txt` 与自身内容                | 拿到新套件、怀疑文件被动过               |
| `check-model.ps1`              | 校验模型文件的字节数与 SHA256                               | 首装、复下载、模型加载报错时             |

## 一、日常一键脚本

### 1. `start-engine.bat` — 一键启动

**用途**：一条命令把引擎拉起来，并在结束前**真发一条请求**证明服务可用。

**怎么用**：双击 `21-launchers\start-engine.bat`（也能在该目录的命令行里执行）。脚本结尾会 `pause`，看完再按键；停机用 `stop-engine.bat`，或直接关掉标题为 `NInfer engine` 的那个窗口。

**它实际做了什么**：

1. 用 `%~dp0` / `%~dp0..` 拼出引擎、模型、启动器三个路径，端口固定 `8095`；
2. `tasklist /FI "IMAGENAME eq ninfer-serve-89.exe"` 查进程，已在运行就跳到"跳过"分支；
3. 依次检查引擎文件、模型文件、启动器是否存在，缺哪个报哪个并退出；
4. 打印 `nvidia-smi --query-gpu=memory.used,memory.total --format=csv,noheader`（脚本提示：引擎大约需要 6.6 GB 空闲显存）；
5. `start "NInfer engine" "%LAUNCHER%"` 另开一个窗口调入 `start-ptq1-mtp-8g-safety.bat`，那个窗口就是实时日志；
6. 轮询 `http://127.0.0.1:8095/v1/models`（`curl.exe -s -o NUL --fail --max-time 5`），最多 60 次、每次约 1 秒；
7. 通了以后再 POST 一条真请求（`model` 为 `qwen3.8-27b`、`temperature` 为 `0`、`max_tokens` 为 `8`，prompt 是 `Reply with exactly: OK`），打印返回的 JSON。

**成功判据**：出现 `[ok   ] the port answered after about <N> seconds.`，且紧接着那条真请求的 JSON 里能看到 `content` 和 `OK`。脚本自己写明了：**`/v1/models` 返回 200 不等于服务活着**，最后那条真请求才是判据。

**失败时会怎样**：

| 屏幕输出                                                | 退出码 | 含义                                          |
| ------------------------------------------------------- | ------ | --------------------------------------------- |
| `[warn ] no answer after 60 seconds.` + 三条排查建议    | 2      | 60 秒没探通，真原因在引擎窗口里               |
| `[skip ] the engine is ALREADY running. Nothing to do.` | 0      | 已在运行，什么都不做                          |
| `[ERROR] engine file not found:`                        | 3      | 找不到 `10-engine\engine\ninfer-serve-89.exe` |
| `[ERROR] model file not found:`                         | 4      | 找不到 `20-model\models\` 下的模型文件        |
| `[ERROR] launcher not found:`                           | 5      | 找不到同目录的 `start-ptq1-mtp-8g-safety.bat` |

**注意事项**：它**硬编码**调用 `-safety` 版启动器，删掉或改名那个文件就会以退出码 5 拒绝，不会退而求其次；端口写死 `8095`，换端口要同步改本脚本与 `stop-engine.bat`；依赖系统自带的 `curl.exe`，显存那行依赖 `nvidia-smi`（随显卡驱动安装）。

### 2. `stop-engine.bat` — 一键停机

**用途**：显示要停的进程 → 询问一次 → 强制结束引擎 → 复查进程、端口、显存。

**怎么用**：双击 `21-launchers\stop-engine.bat`。

**它实际做了什么**：

1. 用 `tasklist` 查 `ninfer-serve-89.exe`，没有就跳到"未运行"分支（端口固定 `8095`）；
2. 打印完整 `tasklist` 输出，让你先看到要停的是哪个进程；
3. `choice /C YN /T 10 /D Y /M "Stop the engine now"`：按 Y 停、按 N 取消，**10 秒不按自动当成 Y**；
4. `taskkill /IM ninfer-serve-89.exe /F`，再用 `ping -n 4 127.0.0.1` 等约 3 秒；
5. 复查三件事：进程列表、`netstat -ano | find ":8095" | find /I "LISTENING"`、`nvidia-smi --query-gpu=memory.used`。

脚本注释写明：引擎**不在磁盘上保存状态**，停机不会丢数据；模型文件和引擎文件从不被触碰。

**成功判据**：`[check] process after stop:` 之后是 `none - the engine is stopped`，`[check] port 8095 listening:` 之后是 `no - the port is free`，显存那行回落到没跑模型的水平。

**失败时会怎样**：`STILL RUNNING - run this file again as administrator`（换管理员权限再跑一次）；端口仍被占时是 `yes - something still holds the port`；本来没跑是 `[skip ] the engine is not running. Nothing to stop.`、按 N 是 `[cancel] nothing was stopped.`，两者退出码都是 0。

**注意事项**：10 秒自动确认是**偏危险**的默认值，窗口开着发呆也会把引擎停掉；它是按**进程名**杀的（`/IM`），不区分是谁启动的，别在同时跑别的引擎实例时用。

### 3. `healthcheck.bat` — 真的活着吗

**用途**：只做一件事 —— 证明引擎在**真的服务**，而不是"端口还在、worker 已经崩了"。

**怎么用**：另开一个窗口双击 `21-launchers\healthcheck.bat`；第一个参数可临时换端口 —— 脚本里是 `if not "%~1"=="" set "PORT=%~1"`，所以 `8095` 是默认值，命令行写 `healthcheck.bat 8095` 即显式指定。

**它实际做了什么**：

1. `curl.exe -s -o NUL -w "%%{http_code}\n"` 打一次 `/v1/models`，**只打印 HTTP 状态码**；
2. 再 POST 一条真请求（`model` 为 `qwen3.8-27b`、`temperature` 为 `0`、`max_tokens` 为 `8`，prompt 同样是 `Reply with exactly: OK`），把返回原文打印出来；
3. `pause` 等你按键。

脚本注释引用了上游手册的原话：**`/v1/models` 返回 200 不是服务的证明** —— worker 崩掉之后它照样返回 200，所以第二步才是唯一的存活判据。

**成功判据**：第一行状态码是 `200`，第二段 JSON 里能看到 `content` 和 `OK`。

**失败时会怎样**：状态码不是 `200`（或 curl 连不上，屏幕上只有空行/报错），第二段没有正常回答 —— 去看引擎窗口的日志，或 `stop-engine.bat` 后重新 `start-engine.bat`。

**注意事项**：它用的是 `curl.exe -s`（**没有** `--fail`），连不上时不会报错退出，只会打出非 200 的码或空行，**必须自己看**；它自己不启动引擎；引擎跑在别的端口时必须显式传参。

## 二、三个启动器

三个启动器共享同一套骨架：定位引擎与模型 → 检查文件存在 → 把引擎目录及其 `x64` 子目录前置到 `PATH` → 设置六个 `NINFER_*` 环境变量 → 打印几行 `[note  ]` → 执行引擎命令行 → 引擎退出后打印 `[engine exited] errorlevel=%ERRORLEVEL%` 并 `pause`。

### 4. `start-ptq1-mtp-8g-safety.bat` — 推荐启动器

**用途**：8 GB 适配的实测基准，**外加两个 B01 防崩开关**；日常就用它。

**怎么用**：双击即可，`start-engine.bat` 也是调它。停止用引擎窗口里的 Ctrl+C，或 `stop-engine.bat`。

**它实际做了什么**：完整命令行与基准启动器逐字相同，**只在末尾多两个开关**：

```bat
--recover-invariant-failures --kv-lease-growth
```

这两个开关**本来就在引擎二进制里**（上游的 bug ledger 扫过已发布的 exe 确认存在），只是上游自己发布的启动器从来没用过。它们针对上游当前头号未修 P0 —— **B01**：超池 prompt 叠加一个大输出租约，会让 worker 以 `Paged KV reservation invariant was violated` 死掉，此后该实例上**每一个请求都返回 503**（僵尸态）。8 GB 卡上的单变量对照实测：请求 `max_tokens` 压到 2048 存活，放到 8192 就打死。

**成功判据**：引擎窗口里出现 `engine ready` 和一行带 `capacity |` 的容量行 —— 启动器回显里就是这么写的：`[note  ] ready when you see "engine ready" and a "capacity |" line`。

**失败时会怎样**：`REFUSE: model file not found:`（退出码 3）或 `REFUSE: engine not found:`（退出码 4）；引擎自己起不来时，窗口里留下引擎报错原文，最后是 `[engine exited] errorlevel=<n>`。

**注意事项**：脚本注释记载的实测结果是 `engine ready`、容量 4,032 tokens、pages 63/1,024、runtime 457.6 MiB、free 560.0 MiB，req#1（1000 进 / 1000 出）TTFT 2.1 s、总 15.9 s、prefill 551.7 tok/s、decode 72.1 tok/s、MTP 接受 779/879 = 88.6%。**诚实说明**（注释原文口径）：`--recover-invariant-failures` 被上游描述为"直接治僵尸态"，而 `--kv-lease-growth` 在一份文档里标 "untested"、后一份 ledger 记 "one external case held"，所以任何改动之后都要重新验证，记录放 `40-docs\notes\`。客户端仍可自己要求超过池子的大小：请求里的 `max_tokens` 请保持 **4032 及以下**，**2048 是实测安全的那个值**。模型路径可覆盖：脚本写的是 `if not defined MODEL set "MODEL=..."`，预先 `set MODEL=...` 即可换模型文件。

### 5. `start-ptq1-mtp-8g.bat` — 基准启动器

**用途**：8 GB 显存适配版的基线，**未被改动的那一份**；另外两个启动器都以它为参照。

**怎么用**：双击或在命令行执行；停止用 Ctrl+C 或 `stop-engine.bat`。

**它实际做了什么**：argv 与 `-safety` 版逐字节相同（少那两个 B01 开关）。注释把性质讲清楚了：这是针对 8 GB 显存的 **documented tier fit（档位适配）**，不是调参。原厂启动器在这台机器上直接跑挂，报错为：

```
requested Engine runtime reservation requires 1863978752 bytes,
but only 1027604480 bytes are available for runtime capacity
```

上游把这种失败命名为"档位不适配，不是引擎缺陷"，本机的应对就是专节二里那几处收窄。

**成功判据**：与 `-safety` 版相同（`engine ready` + `capacity |` 行）；注释里记的实测数字也一致。

**失败时会怎样**：`REFUSE: model file not found:`（3）/ `REFUSE: engine not found:`（4）；显存不足时是引擎自己的 reservation 报错 + `[engine exited] errorlevel=<n>`。

**注意事项**：它**不含** B01 的两个防崩开关 —— 超池 + 大输出租约时，worker 崩掉后整个实例会持续返回 503；它的价值在"对照"：任何新改动都应当能在这份基线上复现原有指标。

### 6. `start-ptq1-mtp-verbatim.bat` — 出厂参数对照

**用途**：把**原厂 argv 原封不动**留下来，让"出厂什么样 / 本机改成什么样"有据可查，而不是口口相传。

**怎么用**：可以双击，但**这台机器上必然失败** —— 脚本自己写着 `DO NOT USE THIS ON THIS MACHINE`；它只在需要复现"原厂配置起不来"这个结论时用。

**它实际做了什么**：只改了路径（原厂的 `.bat` 与它自己的引擎、模型同目录，搬到本树后位置变了），其余每个参数逐字照抄原厂启动器；原厂文件本身未改动，保存在 `40-docs\pack\` 下。与本机适配版的差异是四个数字 —— `--max-context 262144`、`--kv-capacity 17920`、`--host-kv-mib 16384`、`--default-max-tokens 32768`，并且**没有** `--gdn-state-fp16` 和 `--no-cuda-graph`。

**成功判据**：本机没有成功判据 —— 预期结果就是挂掉，屏幕上出现上面那段 reservation 报错。

**失败时会怎样**：引擎立刻以显存预留失败退出，窗口里是 `requested Engine runtime reservation requires ...` 原文，最后 `[engine exited] errorlevel=<n>`。

**注意事项**：三个启动器在 `21-launchers\` 里并存、互不覆盖；想实测原厂参数之前先 `stop-engine.bat`，别让它去抢已经在跑的引擎的显存。

## 专节一：三个启动器的区别

| 文件名                         | 与基准（`start-ptq1-mtp-8g.bat`）的差异                                                                                                                                        | 什么时候用它                              |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------- |
| `start-ptq1-mtp-8g.bat`        | —— 它就是基准                                                                                                                                                                  | 复现基线数据、做对照实验                  |
| `start-ptq1-mtp-8g-safety.bat` | argv 与基准**逐字相同**，只在末尾多 `--recover-invariant-failures`、`--kv-lease-growth`                                                                                        | **日常默认**；`start-engine.bat` 自动调它 |
| `start-ptq1-mtp-verbatim.bat`  | 原厂 argv 逐字：`--max-context 262144`、`--kv-capacity 17920`、`--host-kv-mib 16384`、`--default-max-tokens 32768`，且缺 `--gdn-state-fp16`、`--no-cuda-graph` 与两个 B01 开关 | 只做"出厂 vs 适配"对照；本机跑不起来      |

**推荐 `-safety`，三条理由都不是偏好问题**：

1. **它有基准的全部实测数据背书**：注释记载的同口径复验（decode 72.1 tok/s、MTP 779/879 = 88.6%）与基准逐字相同，说明加那两个开关没有改变任何一项指标。
2. **它防的是上游当前的头号未修 P0（B01）**：超池 + 大输出租约会让 worker 崩成"僵尸"，此后该实例所有请求一律 503；这两个开关正是冲这个状态去的，而且**本来就在引擎二进制里**，是上游自己从未启用的现成能力。
3. **它不牺牲任何东西**：`-safety` 是基准的副本，基准文件保持逐字节不变，随时可以退回基准做对照，不存在"改了就没法回头"的问题。

**唯一要留个心眼的地方**：`--kv-lease-growth` 的证据强度弱于 `--recover-invariant-failures` —— 上游资料里它先是标 "untested"、后又被记了一句 "one external case held"。日常照用没问题，但**每次改动之后都要重新复验**，记录放 `40-docs\notes\`。

## 专节二：启动器参数逐项说明

下面是 `start-ptq1-mtp-8g-safety.bat` 里**照抄**出来的实际命令行（参数名与取值一字未改）：

```bat
"%ENGINE%" "%MODEL%" ^
  --host 127.0.0.1 --port 8095 --model-id qwen3.8-27b ^
  --max-context 65536 --kv-capacity 4032 --kv-dtype k8v4 --host-kv-mib 4096 ^
  --prefill-chunk 1024 --spec mtp --draft-tokens 4 ^
  --default-max-tokens 2048 --default-reasoning-effort none --max-concurrency 1 ^
  --max-shared-prefixes 0 --gdn-state-fp16 --no-cuda-graph ^
  --recover-invariant-failures --kv-lease-growth ^
  --presence-penalty 0 --temperature 0.7 --top-p 0.9 --top-k 20
```

前两个是位置参数：`"%ENGINE%"` 是引擎 exe，`"%MODEL%"` 是模型文件。基准启动器的命令行与此**完全相同，只少最后两个 `--recover-invariant-failures --kv-lease-growth`**。

| 参数                           | 取值          | 为什么这么设                                                                                           | 改了会怎样                                                                                                 |
| ------------------------------ | ------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `--host`                       | `127.0.0.1`   | 只监听本机回环                                                                                         | 改成 `0.0.0.0` 会把服务暴露给局域网，而这个服务**没有任何鉴权**                                            |
| `--port`                       | `8095`        | 全套脚本都按 8095 探活/关停                                                                            | 必须同步改 `start-engine.bat`、`stop-engine.bat` 里写死的 `8095`；`healthcheck.bat` 可用第一个参数临时指定 |
| `--model-id`                   | `qwen3.8-27b` | 客户端请求体的 `model` 字段要填这个名字                                                                | 请求体名字不匹配会被拒；一键脚本与 `healthcheck.bat` 的请求体也写死了这个名字                              |
| `--max-context`                | `65536`       | 原厂 262144；缩到 65536 才能让容量规则（host 页 + device 页 ≥ 逻辑上下文页）成立                       | 调大就超出 host + device 的页数，容量规则不成立、直接回到起不来                                            |
| `--kv-capacity`                | `4032`        | 原厂 17920；4032 = 63 页，是文档里实测过的**最小** device 池                                           | 调大直接多吃显存，8 GB 卡上回到 reservation 失败                                                           |
| `--kv-dtype`                   | `k8v4`        | 原厂原样保留                                                                                           | 相当于换 KV 量化口径，本文所有实测数据作废                                                                 |
| `--host-kv-mib`                | `4096`        | 原厂 16384；把 host 层收窄                                                                             | 调小会让容量规则不成立；调大对 8 GB 显存没有帮助，只是多占系统内存                                         |
| `--prefill-chunk`              | `1024`        | 原厂原样保留                                                                                           | 本机没有实测依据，改了要重新测 prefill                                                                     |
| `--spec`                       | `mtp`         | 开 MTP 投机解码（本机接受率 88.6%）                                                                    | 关掉就退回逐 token 解码，那 88.6% 的加速不再存在                                                           |
| `--draft-tokens`               | `4`           | 原厂原样保留                                                                                           | 调大不必然更快（接受率通常下降）；本机未实测，需复验                                                       |
| `--default-max-tokens`         | `2048`        | 原厂 32768；文档要求请求 `max_tokens ≤ device 池 token 数`，本机单变量对照 2048 存活、8192 打死 worker | 调大就回到 B01 的触发条件（超池 + 大输出租约 ⇒ worker 崩 ⇒ 之后全 503）                                    |
| `--default-reasoning-effort`   | `none`        | 默认关思考，避免少量 `max_tokens` 全花在思考上导致答案被截断                                           | 打开思考必须同步把 `max_tokens` 提到 256 以上，否则答案被截断（读起来像丢针）                              |
| `--max-concurrency`            | `1`           | 单并发，不给 63 页的小池子制造争抢                                                                     | 调大后并发请求会争同一个 device 池                                                                         |
| `--max-shared-prefixes`        | `0`           | 关掉共享前缀，避开"重复发送导致 brick"的那条路径                                                       | 打开即启用共享前缀缓存，正好走回要避开的那条路径                                                           |
| `--gdn-state-fp16`             | 开关          | 文档里的小显存杠杆，8 GB 卡上不加就装不下                                                              | 去掉后引擎无法在 8 GB 上完成 runtime reservation                                                           |
| `--no-cuda-graph`              | 开关          | 实测：正是每个 profile 的 CUDA Graph driver-state 预留让 4032 装不进去                                 | 去掉后回到同一处 reservation 失败                                                                          |
| `--recover-invariant-failures` | 开关          | B01 开关之一：invariant 失败只让**当前请求**失败，而不是杀掉引擎（治僵尸态）                           | 去掉后一次 invariant 失败会让该实例此后所有请求返回 503                                                    |
| `--kv-lease-growth`            | 开关          | B01 开关之二：池子不够时以**有界补全**收尾，而不是抛 invariant                                         | 去掉后回到抛 invariant 的行为；上游对它一处标 "untested"、一处记 "one external case held"，用前先复验      |
| `--presence-penalty`           | `0`           | 原厂采样参数原样保留                                                                                   | 采样行为变化，实测数据不再可比                                                                             |
| `--temperature`                | `0.7`         | 原厂采样参数原样保留                                                                                   | 同上                                                                                                       |
| `--top-p`                      | `0.9`         | 原厂采样参数原样保留                                                                                   | 同上                                                                                                       |
| `--top-k`                      | `20`          | 原厂采样参数原样保留                                                                                   | 同上                                                                                                       |

启动器在起引擎之前还会写六个环境变量（`NINFER_KV_WINDOW=16384`、`NINFER_KV_RETRIEVE=8192`、`NINFER_KV_RING=1`、`NINFER_HOST_PAGEABLE=1`、`NINFER_KV_REUSE_HOSTBACKED=1`、`NINFER_TERNARY_PTQ1_FAST=1`）—— **六个都与原厂一致、未被改动**，注释只说这六行"保持不变"、没有给单变量语义，所以没有实测依据可改。唯一相关的另一个变量是 `NINFER_TERNARY_KVMEM`：**脚本不设置它**，但启动器回显里写明了 content scorer 默认 ON、`NINFER_TERNARY_KVMEM=0` 是它的负对照 —— 只做对照实验时用，日常不要设。

此外启动器会把 `10-engine\engine` 及其 `x64` 子目录前置到 `PATH`，让引擎能从自己的目录加载运行库（不要把 exe 单独拷出去跑，原因见第 7 节）。

## 三、校验脚本

### 7. `verify-arch-engine-8g.ps1` — 单引擎架构验收

**用途**：对**一个**引擎二进制做架构级验收，回答四件事：起得来吗（这一条无法用哈希或文件大小伪造）／超池时警告该响吗／prompt 装得下时警告安静吗／超池 prompt 下答案还对不对。

**怎么用**：`-Exe` 与 `-Tag` 必填，`-Tag` 同时是日志子目录名：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\30-scripts\verify-arch-engine-8g.ps1 `
  -Exe .\10-engine\engine\ninfer-serve-89.exe `
  -Tag sm89-8g `
  -Model .\20-model\models\bonsai2_27b_ternary_ptq1_native_mtp.ninfer
```

**它实际做了什么**：

1. 校验 `-Exe` / `-Model` 存在（缺则 `REFUSE: missing ...`，退出码 3）；`-Model` 默认值是**相对本脚本的路径** `..\20-model\models\bonsai2_27b_ternary_ptq1_native_mtp.ninfer`（在脚本体内用 `$PSScriptRoot` 解析，所以整个目录可以整体搬走），并会自动把 `_mtp.ninfer` 换成 `_native_mtp.ninfer` 再试一次；
2. **运行库同目录检查**：exe 旁边一个 `.dll` 都没有就直接 `REFUSE: no .dll next to ...`（退出码 4），并声明"这是验收台拒绝，不是对引擎的判词"。依据是实测教训：引擎从**自己所在目录**加载运行库，缺 DLL 时**静默失败、stderr 为空**，读起来像引擎坏了；
3. 依次跑三个 arm。每个 arm 都：清掉 7 个 `NINFER_*` 环境变量后重设 6 个 → 组装 argv → 结束同路径的旧引擎进程并等端口空出（最多 30 秒）→ `Start-Process` 起引擎，stdout/stderr 分别重定向到该 arm 目录下的 `out.log` / `err.log` → 轮询 `/v1/models` 直到 200 或超时：

   | arm           | `--kv-capacity`           | 试次 | 期望                                               |
   | ------------- | ------------------------- | ---- | -------------------------------------------------- |
   | `neg-bigpool` | `-BigPool`（默认 32768）  | 2    | 警告**禁止**出现                                   |
   | `pos-mid`     | `-SmallPool`（默认 2048） | 3    | 必须出现警告，且**针在 prompt 中间**时答案要活下来 |
   | `pos-end`     | `-SmallPool`              | 2    | 必须出现警告；针在末尾丢了只记录、不判死           |

4. 每个试次构造约 4.2k token 的填充文本，中间（或末尾）埋一行 `IMPORTANT ARCHIVE CODE: ARCH-<code>`，以 `temperature 0`、`max_tokens 64` 提问；**答案 `finish_reason=length` 或为空一律记为 `INCONCLUSIVE`，绝不算"丢针"**（有实测教训：思考开着时 64 个 token 全花在思考上，读起来和丢针一模一样）；
5. 警告数是数 `err.log` 里 `exceeds the resident Device KV pool` 的行数，并打印 `capacity |` 那一行；最后按 arm 结果汇总判词。

**成功判据**（退出码 0）—— 中间应能看到 `warning_lines=0  (expect 0)`、`warning_lines>=1  (expect >=1)` 以及 `hit=True ans=ARCH-<code>`：

```
RESULT: PASS (warning fires over-pool, silent when it fits, MID-prompt answer survived)
```

**失败时会怎样**：

| 输出                                                                                           | 退出码 | 含义                                              |
| ---------------------------------------------------------------------------------------------- | ------ | ------------------------------------------------- |
| `VERDICT: FAIL (warned when it must not)`                                                      | 1      | prompt 装得下却报警告（对什么都喊狼来了）         |
| `VERDICT: FAIL (silent on an over-pool prompt)`                                                | 1      | 超池了却不报警告                                  |
| `VERDICT: FAIL (mid-prompt needle lost on an over-pool prompt: 0/3)`                           | 1      | **这正是警告存在的意义所指的缺陷**                |
| `VERDICT: INCONCLUSIVE for this arm (every request was truncated/empty)`                       | —      | 全部被截断，该 arm 不成立                         |
| `NOTE: mid-prompt needle partially lost (...)`                                                 | —      | 部分丢针，记录但不判死                            |
| `RESULT: engine did not become servable on this card -> acceptance cannot be claimed locally.` | 2      | 本卡上起不来，不能声称验收通过                    |
| `REFUSE: no .dll next to ...`                                                                  | 4      | 运行库没跟 exe 放一起（验收台拒绝，不是引擎判词） |
| `REFUSE: missing ...`                                                                          | 3      | `-Exe` 或 `-Model` 路径不存在                     |

**注意事项**：**它会杀掉 `-Exe` 指向的那个引擎进程**，并要求 8095 端口空着，跑之前先 `stop-engine.bat`，别在服务正用时跑；它的 argv 里**没有** B01 的两个开关 —— 它测的是引擎默认行为，其中就包含"超池应当报警告"；输出目录是脚本里写死的绝对路径（部署根目录下的 `40-docs\notes\needle\<Tag>\`），搬家后要改这一行；它也从前置 `PATH` 里读一段写死的 CUDA 工具链目录，该目录不存在时是无害的空操作，真正生效的是引擎自身目录 —— 所以**不要**把 exe 单独拷到别的文件夹跑。三个 arm 合计 7 次请求，加上每次引擎启动等待，整体跑十几分钟很正常（`-ReadyTimeoutSec` 默认 300）；`-MaxContext` 默认就压到 65536，为的是让 host 预算守卫（`host_pages + pool_pages >= page_count(max_context)`）能满足。

### 8. `verify-kit-manifest.ps1` — 套件清单逐字节校验

**用途**：把一个套件的 `SHA256SUMS.txt` 与套件自身内容**按字节**比对。

**怎么用**：`-Kit` 必填，`-ShowAll` 连通过项一起打印：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\30-scripts\verify-kit-manifest.ps1 -Kit .\40-docs\pack
```

**它实际做了什么**：

1. 要求该目录里有 `SHA256SUMS.txt`（没有则 `REFUSE: no SHA256SUMS.txt in ...`，退出码 3）；
2. **强制按无 BOM 的 UTF-8 读**清单（`[IO.File]::ReadAllLines($sums, [Text.UTF8Encoding]::new($false))`），并打印套件路径、清单路径、**清单自身的修改时间**、总行数；
3. 逐行按 `^\s*([0-9A-Fa-f]{64})\s{2}(.+?)\s*$` 解析，不匹配的行计入 `unparsed`；
4. 文件存在就 `Get-FileHash` 比 SHA256，一致计 `ok`，不一致打印 `MISMATCH` 加 `want=` / `got=`；
5. 文件不存在时打印 `MISSING`，并把这个文件名的**每个字符码位**（`U+XXXX`）和父目录实际内容一起打出来 —— 这样"编码问题"永远不会被误读成"文件缺失"；
6. 记录覆盖到的最新文件时间；若某个被覆盖文件**比清单还新**，追加一行 `STALE` 警告。

**成功判据**（末行统计，退出码 0）：`ok=<N>  mismatch=0  missing=0  unparsed=0`。

**失败时会怎样**：出现 `MISMATCH` / `MISSING` / `UNPARSED` 中任何一种即退出码 1；`STALE: a covered file is NEWER than the manifest -- the manifest does not describe this kit.` **单独出现时不改变退出码**（仍可能是 0），得自己看这一行；没有清单文件则退出码 3。

**注意事项**：它读的是**无 BOM 的 UTF-8** —— Windows PowerShell 5.1 在中文代码页机器上会把无 BOM 文件当 ANSI 读，那种读法会把非 ASCII 文件名弄成乱码、然后报告"文件缺失"，把**自己的编码 bug 说成包损坏**（假红）。这正是本脚本存在的理由，所以别用别的工具替代它判断套件完整性；`-ShowAll` 只影响打印量，不影响判定。

### 9. `check-model.ps1` — 模型文件校验

**用途**：按**字节数 + SHA256** 校验模型文件；只读，绝不写入、绝不删除。

**怎么用**：默认就指向部署根目录下的 `20-model\models\`，放在 `30-scripts\` 里直接跑即可；换文件或换期望哈希时传参（`-Model`、`-ExpectedBytes`、`-ExpectedSha256`）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\30-scripts\check-model.ps1
```

**它实际做了什么**：取文件长度与 `-ExpectedBytes`（默认 `6394697216`）比对，再算 SHA256 与 `-ExpectedSha256`（默认 `5C4486C8A52687E3F62072C7DD2A320546D0E00D1C019BF137EB02CC944E21B8`）比对，全程打 `MODELCHECK_*` 键值行，最后给一句判词。它默认的模型路径是**由脚本自身位置算出来的**（`$PSScriptRoot` 上一级的 `20-model\models\...`），所以它必须待在部署根目录下的 `30-scripts\` 里。

**成功判据**（退出码 0）：依次出现 `MODELCHECK_SIZE=OK`、`MODELCHECK_HASH=OK`、`MODELCHECK_VERDICT=OK`。

**失败时会怎样**：大小或哈希不符 → `MODELCHECK_SIZE=FAIL` / `MODELCHECK_HASH=FAIL`、`MODELCHECK_VERDICT=FAIL`，并给出 `MODELCHECK_REASON=size or hash mismatch -- re-download, do not start the engine`，退出码 1；文件不在预期位置 → `MODELCHECK_VERDICT=MISSING` 加一行 `MODELCHECK_PATH=...`，退出码 3。

**注意事项**：6.4 GB 的文件算一次 SHA256 要几秒到几十秒，脚本会先打印 `MODELCHECK_HASHING=started (this takes a few seconds on 6.4 GB)`，别以为它卡住了。本树里的引擎包**不含模型及其 `MODELS.txt` 清单** —— 模型是**单独交付**的，所以本机没有上游 sha256 可比：能查的是①上游教程对这个产物给出的字节数、②本部署**首次放置该文件时记录的** sha256，后者能抓住"之后被损坏"，抓不住"一开始就下错"。换过模型就必须同步换 `-ExpectedBytes` / `-ExpectedSha256`。

## 专节三：脚本的通用约定

### 1. 批处理脚本 100% 纯 ASCII（包括注释）

这不是洁癖，是 `cmd` 的解析规则：`.bat` 按 **OEM/ANSI 代码页**解析，注释行里出现一个非 ASCII 字节，这一行就**不再是注释**，碎片会被当成命令执行；而注释或带引号的 `echo` 里出现一个 `)`，又会**提前关闭**外层块（`if not exist (...)` 那种）。这两个坑在搭建这套脚本时都踩过，所以所有 `.bat` 的注释与回显一律纯英文。**推论**：往这些文件里加中文注释会真的把脚本弄坏，不是"可能"。

### 2. 用 `ping` 做延时，不用 `timeout`

等待一律写成 `ping -n 2 127.0.0.1 >NUL`（约 1 秒）或 `ping -n 4 127.0.0.1 >NUL`（约 3 秒）。原因写在注释里：**`timeout` 在 stdin 被重定向时会中止** —— 从另一个脚本调用、或输入被重定向时轮询就断了；`ping` 在任何情况下都管用。

### 3. 用 `%~dp0` 相对定位，不用绝对路径

启动器用 `%~dp0`（脚本自身目录）和 `%~dp0..`（部署根目录）拼出引擎与模型路径；三个 PowerShell 脚本都用 `$PSScriptRoot` 解析相对默认值（`verify-arch-engine-8g.ps1` 的日志目录默认落在 `data\needle\<Tag>\`，`-Model` 默认值指向 `..\20-model\models\`）。好处是**整个目录可以整体搬走**，换盘符、换上级路径都不用改内容——**没有需要手工改的例外**。

### 4. 端口与模型名是全局约定

`8095` 与 `qwen3.8-27b` 被多个脚本写死（`start-engine.bat`、`stop-engine.bat`、`healthcheck.bat` 的请求体、启动器的 `--port` / `--model-id`）。这是刻意的：一键脚本要能在零配置下工作。代价是改端口/改模型名时**必须多处同步改**，`healthcheck.bat` 是唯一支持参数覆盖端口的那个。

### 5. 退出码约定

| 退出码 | 通用含义                                                                                                                               |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `0`    | 成功（或"本来就不需要做事"：已在运行 / 没在运行 / 用户取消）                                                                           |
| `1`    | 校验判定为 FAIL（三个校验脚本）                                                                                                        |
| `2`    | 等不到服务：`start-engine.bat` 60 秒超时；`verify-arch-engine-8g.ps1` 引擎在本卡上起不来                                               |
| `3`    | 关键文件缺失：启动器缺模型、`check-model.ps1` 缺模型、`verify-kit-manifest.ps1` 缺清单、`verify-arch-engine-8g.ps1` 缺 `-Exe`/`-Model` |
| `4`    | 启动器缺引擎文件；`verify-arch-engine-8g.ps1` 的 exe 旁边没有 `.dll`                                                                   |
| `5`    | `start-engine.bat` 找不到同目录的 `-safety` 启动器                                                                                     |

`3` / `4` 的具体含义在不同脚本间略有出入，以上表为准，必要时回看各脚本小节。

### 6. 只读优先、双击友好

`check-model.ps1` 与 `verify-kit-manifest.ps1` 是纯只读的：只算哈希、只打印，从不写、从不删。`stop-engine.bat` 动手之前先把进程列表打出来，然后才问一次；引擎不落盘状态，停机不会丢数据。唯一的例外是 `verify-arch-engine-8g.ps1`：它会**启停引擎并写日志**，还会结束同路径的旧引擎进程 —— 所以它是唯一一个跑之前要先确认"现在没有正在用的服务"的脚本。

所有一键脚本结尾都 `pause`，双击运行后窗口不会一闪而过；校验脚本是命令行工具（`.ps1` 默认不能双击运行），请在终端里用 `powershell -NoProfile -ExecutionPolicy Bypass -File ...` 调用，并把结果整段复制下来存档。
