# 11 · 脚本与工具说明

本仓库 `scripts\` 共 **13 个文件**：6 个一键批处理 + 4 个 PowerShell 实现 + 3 个校验/验收脚本。
本文逐个说明**怎么用、它实际做了什么、看什么输出算成功**，最后统一交代通用约定与分发包自带工具。

> **口径**：只写脚本里真实存在的行为，参数名、取值、屏幕输出照抄脚本原文。
> 命令按部署后的目录树书写：一键脚本与 `start-tier.ps1` 等在 `21-launchers\`，校验脚本在 `30-scripts\`。
> 本仓库 `scripts\` 只是**副本**，复制到部署根对应目录后使用（见 §5）。

## 一、日常一键脚本（6 个 .bat）

批处理只做三件事：`cd /d "%~dp0"` → 用系统 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File`
调用对应 `.ps1` → 非 0 退出码时 `pause`（双击窗口不闪退）。

| 脚本              | 实际调用                                                                                | 用法 |
| ----------------- | --------------------------------------------------------------------------------------- | ---- |
| `start-daily.bat` | `start-tier.ps1 -Tier daily`                                                            | 双击 |
| `start-long.bat`  | `start-tier.ps1 -Tier longctx`                                                          | 双击 |
| `stop-daily.bat`  | `stop-tier.ps1 -Tier daily`                                                             | 双击 |
| `stop-long.bat`   | `stop-tier.ps1 -Tier longctx`                                                           | 双击 |
| `healthcheck.bat` | `healthcheck.ps1`                                                                       | 双击 |
| `open-ui.bat`     | 直接用包内 `python.exe launcher.py --no-browser` 拉起，再 `start http://127.0.0.1:8720` | 双击 |

> 全部批处理**纯 ASCII、CRLF**（仓库 `.gitattributes` 已钉死）。不要用 UTF-8 带 BOM 保存，
> 也不要把中文注释写进 `.bat`（cmd 会按 OEM 代码页解析，注释可能变成命令）。

## 二、四个 PowerShell 实现

### 7. `start-tier.ps1` — 启动（有参数）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\21-launchers\start-tier.ps1 -Tier daily
#    -Tier：只接受 daily | longctx（必填）
```

**执行顺序（照脚本原文）**：

1. 读 `_common.ps1` 的常量：`TierProfiles`（daily→`8g-daily`，longctx→`8g-longctx`）、`RedlineMiB=7488`。
2. `nvidia-smi --query-gpu=memory.used,memory.total` 打印当前显存；失败直接退出（`exit 1`）。
3. `Ensure-LauncherUi`：8720 没在听就用包内 python 拉起 `launcher.py --no-browser`（最小化窗口），等端口 30 s。
4. 查 `/api/state`：
   - 已经在跑**同一档** ⇒ 打印 `[skip]` + 汇总，`exit 0`；
   - 在跑**另一档** ⇒ 先 `/api/stop` 停掉再切（失败 `exit 1`）；
   - 8080/8081 被占但 launcher 无归属进程 ⇒ 尝试停止。
5. `/api/preflight`（预检）：不通过打印 `code: message` + `fix:`，**`exit 2`**。
   通过则打印 `[ok] budget gate: engine=… MiB, redline=… MiB`。
6. `/api/start`（起引擎+网关）：失败打印 `error.code/message` 与引擎日志尾部，**`exit 3`**。
7. 打印汇总（档位、engine/gateway/UI 三个 URL、引擎日志路径、当前显存、红线、停机命令）。
8. **真发一条请求**（`Reply with exactly: OK`，`max_tokens=8`）：
   - 内容含 `OK` ⇒ `[done] the service is REALLY serving.` **`exit 0`**；
   - 请求失败或内容不含 `OK` ⇒ 警告并 **`exit 4`**（引擎可能还在预热）。

**退出码**：0 成功 / 1 环境或 UI 失败 / 2 预检拒绝 / 3 启动失败 / 4 真请求验证失败。

### 8. `stop-tier.ps1` — 停机（有参数）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\21-launchers\stop-tier.ps1 -Tier daily
#    -Tier：daily | longctx（默认 daily；两档都停同一个 launcher 归属实例）
```

**行为**：

- 8720 没在听 ⇒ `[skip]`；若 8080/8081 仍在听则 `exit 1` 并提示手动处理。
- 有 launcher ⇒ 查 `/api/state`；没在跑 ⇒ `[skip]`，`exit 0`。
- `POST /api/stop`（**只停 pid.json 里记录的进程，绝不按镜像名 taskkill**），打印被停的 engine/gateway pid。
- 轮询 20 s 确认端口关闭，打印 `port 8080/8081 listening` 与当前显存。
- 端口仍开 ⇒ `exit 1`；否则 `[done] the engine is stopped.` `exit 0`。

> **停机后显存应回到空闲基线**（引擎占用约 7 GB 全部释放）。控制台窗口可以留着（不占显存）。

### 9. `healthcheck.ps1` — 体检（无参数）

**行为**：

1. `GET http://127.0.0.1:8080/v1/models`：能连上打印 `[ok] … (this alone is NOT proof of service)`；失败 `exit 1`。
2. 真发一条请求（`Reply with exactly: OK`，`max_tokens=8`，超时 120 s），打印 `content / finish / usage`。
3. 若 launcher 在跑，打印当前 profile 与 engine/gateway alive 状态、网关 baseURL 提示、显存。
4. 内容含 `OK` ⇒ `[PASS ] the engine is really serving.` `exit 0`；否则 `exit 1`。

## 三、校验与验收脚本（3 个 .ps1，放 `30-scripts\`）

### 11. `verify-engine-package.ps1` — 引擎包完整性

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\30-scripts\verify-engine-package.ps1
#    可选 -Pkg <包根>（默认 部署根\10-engine）
```

**做什么**：

- 读 `10-engine\SHA256SUMS.txt`（68 条），逐条重算 sha256 对比；
- `launcher.py` / `profiles.json` 两项是**本地两档补丁**，白名单放行（记 `DEVIATED`），
  并用 `_migration-v2\pristine\*.orig-dist` 复核"原件哈希 = 出厂哈希"；
- 最后打印 `SUMMARY ok=… mismatch=… missing=… deviated=… unparsed=…`。

**判据**：`RESULT: PASS`，即 `mismatch=0` 且 `missing=0`。
打过补丁的包应为 `ok=66 mismatch=0 missing=0 deviated=2`；未打补丁应为 `ok=68`。
**退出码**：0 PASS / 1 FAIL / 3 找不到清单。

### 12. `check-model.ps1` — 模型件校验

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\30-scripts\check-model.ps1
#    可选 -Model / -EngineLink / -ExpectedBytes / -ExpectedSha256
```

**做什么**：

1. 检查两个路径存在：`20-model\models\bonsai2_…ninfer`（正本）与 `10-engine\model\bonsai2_…ninfer`（硬链接）；
2. 打印字节数与 `LinkType`，字节数必须 = **6,394,697,216**；
3. 计算正本 sha256（约 10~30 s），必须 = `5C4486C8A52687E3F62072C7DD2A320546D0E00D1C019BF137EB02CC944E21B8`；
4. 再算引擎侧文件 sha256，必须与正本一致（证明是**同一份字节**，不是复制的一半）。

**判据**：

```text
MODELCHECK_VERDICT=OK
MODELCHECK_BYTES=OK
MODELCHECK_HASH=OK
```

**退出码**：0 OK / 1 FAIL。

### 13. `verify-v2-basic.ps1` — 运行中两档基础验收

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\30-scripts\verify-v2-basic.ps1 -Tier daily
#    -Tier daily|longctx（默认 daily）
#    -OutputTokens 4096  可加做长输出测试（很慢，几分钟）
```

**8 项检查**（脚本原文顺序）：

1. **launcher 状态**：`/api/state` 可达；`selected_profile` 必须等于目标档；engine/gateway 进程 alive。
2. **`GET /v1/models`**（引擎 8080）返回 200。
3. **显存红线**：`nvidia-smi` 采样 ≤ **7,488 MiB**。
4. **真请求**：`Reply with exactly: OK`，回答含 `OK`。
5. **能力探针**：`7*5` → 含 `35`；同一会话追加 `+2` → 含 `37`。
6. **4 条互不相同的连续请求**：4/4 都含 `OK`（验证"只服务第一条请求"修复）。
7. **`capacity` 行**：从最新引擎日志取 `capacity | KV …`，必须匹配目标档池（12,800 / 51,200）且 dtype = `rk2v4-e8`。
8. **可选长输出**（`-OutputTokens > 0`）：计数语料强制输出，`completion ≥ 0.9 × max_tokens` 判 PASS。

**判据**：末行 `RESULT: PASS`；否则 `RESULT: FAIL` 并列出 `[FAIL]` 项。
**退出码**：0 PASS / 1 FAIL。**前置**：对应档位已在运行。

## 四、上游工具（不在本仓库内，需要时从上游取）

上游源码仓 <https://github.com/1314521gjy/ninfer-fusion-kvmem> 的 `tools\` 下有三个 Python 工具
（Apache-2.0；本仓库**不随附**，避免与上游原件混淆）：

| 工具             | 用途                                                                                                         | 前置                            | 入口命令（示例）                                                                                                                                            |
| ---------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `agg_gateway.py` | **超池分片聚合网关**：按结构单元打包、逐片摘要回注、`unit_broken` 拒答（不回落模型 reduce；附 `--selftest`） | 需引擎在跑（`--selftest` 除外） | `python tools/agg_gateway.py --prompt-file <材料> --question <问题> --pool-tokens 51200 --base-url http://127.0.0.1:8080`                                   |
| `kv_plan.py`     | **容量规划（纯算术）**：按 vram / quant / context 算池页数与 engine 预估；带 `PAGE_BYTES` 表与 `--selftest`  | 不需要引擎（stdlib）            | `python tools/kv_plan.py --vram-gib 8 --quant ptq1 --context 262144 --host-kv-mib 3328`                                                                     |
| `accept_8g.py`   | **8G 档端到端验收**：6 个 streaming case + 引擎/网关日志 + GPU/内存采样判 GREEN/RED（退出码 0/1）            | 需引擎+网关在跑                 | `python tools/accept_8g.py --gateway http://127.0.0.1:8081 --engine-log <log> --gateway-log <log> --filler <filler.txt> --pool 51200 --engine-max-mib 7488` |

**注意**：

- `kv_plan.py` 的默认预留/桌面口径可能与分发包 `profiles.json` 不同——**以本方案实测配方为准**
  （日常 7,421 / 长档 7,312 ≤ 7,488）。
- `agg_gateway.py` 的 `--max-shard-tokens` 必须 **≤ 池**（日常 12,800 / 长档 51,200）。
- `accept_8g.py` 的默认日志/filler 路径是上游开发机路径，换机必须用参数覆盖；本方案日常验收用
  `verify-v2-basic.ps1` 即可。

## 六、脚本通用约定

1. **批处理纯 ASCII、CRLF**：cmd 按 OEM 代码页解析 `.bat`，非 ASCII 字节会让注释行变成命令。
   仓库 `.gitattributes` 已钉死：`.bat`/`.ps1`=CRLF、`*.md`=LF；检出后不要手工改换行。
2. **相对路径定位**：批处理用 `%~dp0`，PowerShell 用 `$PSScriptRoot` / `Split-Path -Parent`；
   整套目录可以整体搬走，只要保持 `10-engine\` / `20-model\` / `21-launchers\` 的层级。
3. **Windows PowerShell 5.1 兼容**：不用 PS7 独有语法（如三参数 `Join-Path`）；`-NoProfile -ExecutionPolicy Bypass`。
4. **只停自己启的进程**：停机走 launcher 的 `/api/stop`（按 `run\pid.json` 记录），**绝不按镜像名 taskkill**。
5. **只读优先、双击友好**：校验脚本不改任何引擎/模型文件；一键脚本非 0 退出码时 `pause`。
6. **判据输出**：成功关键字 `[ok]` / `[PASS ]` / `RESULT: PASS` / `MODELCHECK_VERDICT=OK`；
   失败 `[FAIL ]` / `RESULT: FAIL`；启动汇总打印档位、URL、日志路径与显存。
7. **端口与模型名是全局约定**：引擎 8080、网关 8081、控制台 8720、模型 id `j27b`。
   改端口要同时改 `profiles.json`、网关参数与脚本常量——**不建议**。

## 七、常见改动与注意

| 想改什么            | 怎么改                                                                                 | 注意                                                       |
| ------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 加一个新档位        | `profiles.json` 的 `profiles[]` 加一项（参照 [04 附录 A](04-8GB显存档位适配.md)）      | 受保护开关不能进 `extra_argv`；跑 `launcher.py --selftest` |
| 改默认输出上限      | profile 的 `default_max_tokens` + `gateway_headroom_tokens`（= 输出+512）              | 别超过池；改完跑两档验收                                   |
| 改超时              | `_common.ps1` 的 `Invoke-Chat` 超时参数 / 客户端超时                                   | 长档 8k 输出 6~7 分钟，别设太短                            |
| 改红线              | `_common.ps1` 的 `RedlineMiB`                                                          | 红线必须 ≤ 卡容量 − 预留 − 桌面；别为了"能启动"硬调高      |
| 换脚本输出语言/格式 | 可以，但保留 `RESULT: PASS` 等**判据关键字**                                           | 自动化依赖这些关键字                                       |
| 升级上游分发包      | 重新打两档补丁（[04 附录 A](04-8GB显存档位适配.md)），重跑 `verify-engine-package.ps1` | 补丁只对 2026-10-19 r3 分发包验证过                        |
