# 01 · 方案总览

> 这篇是入口。看完它你应该能回答三个问题：**这套东西是什么、它能干什么、它不能干什么。**

---

## 1. 一句话

**在一张 8 GB 显存的笔记本显卡上，用 KV 流式引擎把 27B 参数的三进制量化模型跑成"可用的本地长上下文助手"，
并给出两档配置：日常快档与长上下文档。**

"可用"的定义不是"能启动"，而是：

- 能起（`engine ready` + `capacity` 行 + 显存峰值 ≤ 红线）
- 能答对（数数字判据 `7*5 → 35`、`+2 → 37`）
- 能连续服务（4 条互不相同的请求 4/4 通过，v1 时代"只服务第一条请求"的缺陷已修）
- 能长输出（日常档 2,048 配置上限，旧配置 4,096 实测吐满；长档 8,192 实测吐满）
- 能长上下文检索（池内题面中段针命中）
- **知道自己在哪会坏**（缺陷清单、绕法与边界）

## 2. 这套方案的三个组成部分

| 部分       | 是什么                                                                                            | 本仓库提供什么                                               |
| ---------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| **引擎**   | NInfer v2（KV 流式）`infer-serve.exe`，一包三 arch（sm86 / sm89 / sm120a），OpenAI 兼容 HTTP 接口 | 完整的启动参数、两档 profile、判据与适配结论；**不含二进制** |
| **模型**   | Bonsai 2 27B 三进制量化件（PTQ1_0，6.4 GB，自带 MTP 头）                                          | 校验方法、组件探测结论；**不含权重**                         |
| **适配层** | 让这两样在 8 GB 卡上真正跑起来、并且分成两档的那一堆参数、开关、脚本与判据                        | **全部内容**（本仓库主体）                                   |

> **关键认知**：这个项目的价值不在"下载模型然后双击"，而在**第三层**——
> 出厂配方在 8 GB 卡上**直接起不来**（CUDA Graph 预留 + 全局 262k 上下文），必须做档位适配；
> 而适配的每一步都有代价，本仓库把每一步的**依据、实测结果和代价**都写清楚了。

## 3. 方案包含什么（清单）

### 3.1 两档配置（v2 核心）

| 项                                  | 日常推荐 `8g-daily`    | 长上下文 `8g-longctx`  |
| ----------------------------------- | ---------------------- | ---------------------- |
| 设备 KV 池（可信单题面上限）        | **12,800**（200 页）   | **51,200**（800 页）   |
| 逻辑窗口 `--max-context`            | **131,072**            | **262,144**            |
| 默认输出上限 `--default-max-tokens` | **2,048**              | **8,192**              |
| dtype / host KV                     | `rk2v4-e8` / 3,328 MiB | `rk2v4-e8` / 3,328 MiB |
| 投机解码                            | MTP `draft_tokens=4`   | 无                     |
| 网关输入预算                        | **10,240**              | **42,496**             |
| 显存峰值（实测）                    | 7,015 MiB              | 7,171 MiB              |

细节与依据：[04 · 8 GB 两档配置](04-8GB显存档位适配.md)。

### 3.2 显存与稳定性必需项（缺一不可）

| 项                                | 值                 | 不做会怎样                                                                  |
| --------------------------------- | ------------------ | --------------------------------------------------------------------------- |
| `--no-cuda-graph`                 | **两档都加**       | 首启 FATAL：runtime reservation 1,426 MiB > 可用 1,020 MiB                  |
| `NINFER_HOST_PAGEABLE=1`          | **必须在**         | 主机 KV 层失效（`host_kv_arena is null`），长上下文机制等于不工作           |
| `--default-reasoning-effort none` | **两档都设**       | 默认 `medium` 时短请求 token 全进 reasoning 通道，正文为空                  |
| MTP `draft_tokens=4`              | **日常档**         | draft=1 时 decode 只有 36~37 tok/s（draft=4 后 63~72，显存不变）            |
| `--max-shared-prefixes 0`         | **启动器强制注入** | 环模式下共享前缀快照会抛 `active KV snapshot page ownership is not ordered` |
| 网关 input headroom               | 输出上限 + 512     | 网关无法保证"题面 + 输出 ≤ 池"，超池静默截断风险上升                        |

### 3.3 判据与验收

不靠"感觉能跑"，靠**能变红的判据**：

| 判据           | 通过标准                                                                        |
| -------------- | ------------------------------------------------------------------------------- |
| 真请求判活     | 一键启动 / 体检脚本结尾的 `[proof]` / `[PASS]`（**不是** `/v1/models` 200）     |
| 能力探针       | `7*5` → `35`，追加 `+2` → `37`                                                  |
| 连续请求       | 4 条互不相同的请求 `4/4 200`                                                    |
| 容量行         | `capacity \| KV 12,800/51,200 tokens, rk2v4-e8, explicit \| pages …` 与档位一致 |
| 预算闸门       | 日常 7,421 ≤ 7,488；长档 7,312 ≤ 7,488                                          |
| 显存红线       | 运行中 `nvidia-smi` 采样 ≤ 7,488 MiB                                            |
| 长输出（可选） | `max_tokens=2048/8192` 时 `finish=length` 且 completion 达到上限                |
| 包 / 模型校验  | `RESULT: PASS`；`MODELCHECK_VERDICT=OK`                                         |

原始读数与复现命令：[05 · 实测数据与验收](05-实测数据与验收.md)。

### 3.4 工具与文档

- **两档一键脚本**：启动（预检 + 真请求验证）、停机（只停 launcher 记录的进程）、体检、开控制台
- **校验脚本**：引擎包逐文件校验、模型件校验、运行中两档基础验收
- **分发包自带**：控制台 UI（8720）、网关（8081，L0~L3 让位阶梯）、MCP（stdio，5 工具）
- **文档十一篇**：从零基础入门到排错手册

## 4. 实测能力边界

| 项目       | 实测值                                          | 含义                                              |
| ---------- | ----------------------------------------------- | ------------------------------------------------- |
| 可信单题面 | 日常 **12,800** / 长档 **51,200** token         | 题面 + 输出 ≤ 池 才可信                           |
| 逻辑窗口   | 日常 131,072 / 长档 262,144 token               | 提问 + 回答一起算；超出池的部分走检索/主机层      |
| 主机 KV 层 | **3.25 GiB pinned**（另有 host state 1.15 GiB） | 放不下的 KV 降到内存                              |
| 解码速度   | 日常 **63 ~ 72 tok/s** / 长档 **20 tok/s**      | 日常档 1,000 字约 15 s；长档 8k 输出约 6 分 45 秒 |
| 预填速度   | **610 ~ 697 tok/s**                             | 1,000 token 题面约 1.5 s                          |
| TTFT       | 1.7 s（1,121 token 题面）；长档 48k 题面 78.7 s | 长档代价明确                                      |
| 并发       | **1（单路）**                                   | 同一时刻只服务一个请求，其余排队                  |
| 模态       | 纯文本                                          | 无视觉塔                                          |
| 显存占用   | 7,015 / 7,171 MiB（红线 7,488）                 | 跑引擎时别开游戏                                  |
| 知识       | 离线                                            | 不知道训练之后的事                                |

## 5. 三条"反直觉但实测"的结论

### 5.1 一个档位不够，要两个（而且长档明显慢）

8 GB 卡上"长上下文"和"快"不能同时拿满：日常档把池压到 12,800 换 MTP draft4 的 **63~72 tok/s**；
长档把池抬到 51,200、去掉 MTP，换来 48k 题面一次性喂入，代价是 **20 tok/s**、8k 输出要 6~7 分钟。
**选哪个先看任务，不是先看参数表。**

### 5.2 逻辑窗口 ≠ 可信窗口

日常档逻辑窗 131,072、长档 262,144 看着很大，但 **8 GB 上真正可信的单题面是池**（12,800 / 51,200）。
超过池时引擎会打 `prompt exceeds the resident Device KV pool … unverified` 告警；
上游口径明确：**题面 token > 池 token ⇒ 单请求答案不可信**，而且**"没打警告"不等于安全**。

### 5.3 最危险的失败不是"报错"，是"静默答错"

| 现象                                        | 危险点                                                                                           |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 超池题面的中段可能**静默丢失**              | HTTP 200、`finish_reason=stop`、答案却漏了中间内容（引擎日志有 `unverified` 告警，客户端看不到） |
| worker 崩了之后 `/v1/models` **仍返回 200** | 健康检查骗人，必须真发请求                                                                       |
| 网关让位（L1）会丢弃最旧的非 system 消息    | 实测单条超大历史消息被整条丢弃，模型诚实回答"我没有访问任何密码"                                 |
| 客户端不写 `max_tokens`                     | 服务端默认上限静默截断（B37），长输出任务表现为"写一半停了"                                      |

因此本方案的一条核心纪律：**任何"看起来正常"都不能当证据，必须有判据。**

## 6. 现在这台机器上的最终配置（一页可抄）

```text
启动   ： 21-launchers\start-daily.bat（日常） / start-long.bat（长档）     ← 双击
停机   ： 21-launchers\stop-daily.bat（或 stop-long.bat）
体检   ： 21-launchers\healthcheck.bat
控制台 ： 21-launchers\open-ui.bat  → http://127.0.0.1:8720

日常档 ： 池 12,800 / ctx 131,072 / 默认输出 2,048 / MTP draft4 / 网关预算 10,240
          capacity: KV 12,800 tokens, rk2v4-e8, explicit | pages 200/2,048 | runtime 675.6 MiB | free 340.0 MiB
          显存峰值 7,015 MiB（红线 7,488）· decode 63~72 tok/s · 旧配置 4,096 输出可达（现配置上限 2,048）
长档   ： 池 51,200 / ctx 262,144 / 默认输出 8,192 / 无 MTP / 网关预算 42,496
          capacity: KV 51,200 tokens, rk2v4-e8, explicit | pages 800/4,096 | runtime 1.11 GiB | free 310.0 MiB
          显存峰值 7,171 MiB · decode 20 tok/s · 8,192 输出可达（404.6 s）

必带   ： --no-cuda-graph · NINFER_HOST_PAGEABLE=1 · --default-reasoning-effort none
          · --max-shared-prefixes 0（启动器注入）· 日常档 MTP draft 4
env    ： NINFER_KV_WINDOW=10240 · NINFER_KV_RETRIEVE=8192 · NINFER_KV_REUSE_HOSTBACKED=1
         · NINFER_HOST_PAGEABLE=1
客户端 ： baseURL http://127.0.0.1:8081/v1（网关）或 8080（引擎直连）· model j27b
         显式 max_tokens（≤2048 / ≤8192）· 题面+输出 ≤ 池 · 超时 ≥300 s
已知界 ： 单路 · 纯文本 · 离线 · 未鉴权（仅 127.0.0.1）· 上游 B33/B35/B36/B37 未修
```
