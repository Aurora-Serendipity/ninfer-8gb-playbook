# 02 · 硬件与软件基线

> 复现前先对照这一篇。**换机器后速度类数字必须重测**——上游多篇文档自己就写着"别照用数字"。

## 1. 硬件

| 项目     | 本机实测值                               |
| -------- | ---------------------------------------- |
| GPU      | **NVIDIA GeForce RTX 4060 Laptop GPU**   |
| 架构     | **sm_89**（Ada，compute capability 8.9） |
| 显存     | **8,188 MiB**（≈ 8 GB）                  |
| 系统内存 | **32 GB**                                |
| 操作系统 | Windows x64                              |

**为什么强调 sm_89**：上游分发的引擎是**按架构编译**的，本套件只含 sm_89 版本；
其它架构会被启动件直接拒绝（**是拒绝，不是降级或回退**）。

## 3. 引擎与模型件的身份（哈希是唯一可信标识）

### 3.1 引擎

| 项     | 值                                                                 |
| ------ | ------------------------------------------------------------------ |
| 文件名 | `ninfer-serve-89.exe`                                              |
| 字节数 | **1,511,845,888**                                                  |
| sha256 | `19222A2A68DF6F7D87889EE3B33BEDF2F3486EA309B6394A8F8A1A412262771E` |

这条哈希有实际意义：上游存在过一个**混合目标文件的错误构建**（会在特定路径上崩溃）。
上面这个哈希对应的是**干净构建**，也是本方案验收时使用的那个。

### 3.2 模型件

| 项       | 值                                                                 |
| -------- | ------------------------------------------------------------------ |
| 文件名   | `bonsai2_27b_ternary_ptq1_native_mtp.ninfer`                       |
| 字节数   | **6,394,697,216**（5.96 GiB；引擎日志报 **5.94 GiB**）             |
| sha256   | `5C4486C8A52687E3F62072C7DD2A320546D0E00D1C019BF137EB02CC944E21B8` |
| 组件     | `mtp, text`（**无视觉塔**）                                        |
| 投机解码 | 支持 `mtp` 档，推荐 `--spec mtp --draft-tokens 4`                  |

### 3.3 怎么自己核一遍

```powershell
# 引擎哈希
Get-FileHash -Algorithm SHA256 .\10-engine\engine\ninfer-serve-89.exe

# 模型件哈希与长度
Get-FileHash -Algorithm SHA256 .\20-model\models\bonsai2_27b_ternary_ptq1_native_mtp.ninfer
(Get-Item .\20-model\models\bonsai2_27b_ternary_ptq1_native_mtp.ninfer).Length
```

模型件还应该跑一次**组件自检**（本方案用的脚本在 `scripts\check-model.ps1`）。
本机实测输出要点：

```text
MODELCHECK_VERDICT=PASS
LENGTH_MATCH=YES
COMPONENTS=mtp,text
HAS_DFLASH2=NO
HAS_VISION=NO
SPEC_CHOICES=mtp
RECOMMENDED_ARGV=--spec mtp --draft-tokens 4
```

## 5. 哪些数字可以照抄，哪些必须重测

| 类别           | 例子                                                              | 换机器后                      |
| -------------- | ----------------------------------------------------------------- | ----------------------------- |
| **结构性事实** | 上下文 65,536 · 池 4,032 · 单路并发 · 无视觉 · 参数名与语义       | ✅ 可以照抄                   |
| **判据**       | `7*5`→`35`、`RESULT: PASS`、`cache ≥ 90%`、不变量 0 行            | ✅ 可以照抄                   |
| **速度类数字** | decode 72 ~ 78 tok/s · prefill 550 ~ 672 tok/s · TTFT 1.7 s · 启动 3.3 ~ 3.5 s | ❌ **必须重测**               |
| **负结果**     | 池 8,192 变慢 38%                                                 | ⚠️ 机制可参考，**幅度需重测** |

> 上游参考机（RTX 4080 SUPER）的解码是 **194.6 token/s**，本机是 **72 ~ 78 token/s**（三次同口径复测：72.1 / 72.2 / 78.4）。
> 同一个模型、同一套判据，差 **2.7 倍**——这就是为什么"照用数字"是错的。

## 6. 路径约定（会影响能不能跑起来）

- **部署根目录必须是纯 ASCII 路径**（例如 `D:\llm-deploy\`）。
  历史坑：非 ASCII 目录 + 无 BOM 的 `.ps1` 会被 PowerShell 5.1 按 ANSI 读 ⇒ 路径静默乱码 ⇒
  **检查全绿但对象不存在**。
- 启动器与脚本内部全部使用**相对路径**（`%~dp0..`），所以整个目录可以整体搬走，
  只要保持 `10-engine\` / `20-model\` / `21-launchers\` 的层级关系。
- 批处理启动器**必须是纯 ASCII、无 BOM**（含注释）：cmd 会按 OEM 代码页解析 `.bat`，
  非 ASCII 字节会让注释行变成命令。
