# 04 · 8 GB 档位适配（本方案的技术核心）

> 出厂配方在这张卡上**起不来**，而且出厂只有"8G 长档 / 8G 快档"两个近似档、缺分区参数。
> 这一篇讲清楚：**为什么起不来、两档各改了什么、每处的代价是什么、显存预算怎么算、
> 以及显存不够时按什么顺序退。**

---

## 1. 为什么出厂配方装不下

8 GB 显存要同时容纳四样东西：

| 项                                      | 日常档实测                | 长档实测               |
| --------------------------------------- | ------------------------- | ---------------------- |
| 模型权重                                | **5.94 GiB**（含 MTP 头） | **5.52 GiB**（无 MTP） |
| 设备 KV 池 + 工作区（引擎报 `runtime`） | **675.6 MiB**             | **1.11 GiB**           |
| 引擎余量（引擎报 `free`）               | 340.0 MiB                 | 310.0 MiB              |
| 主机层不占显存（钉在内存）              | —                         | —                      |

而出厂配置里还有四处"在 8 GB 卡上必然出问题"的设置：

| 出厂设置                                                                | 后果                                                                                                                                                |
| ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| **CUDA Graph 预留**                                                     | 首启 FATAL：`requested Engine runtime reservation requires 1494896128 bytes, but only 1069547520 bytes are available`（1,426 MiB > 可用 1,020 MiB） |
| `common_argv` 全局 `--max-context 262144` / `--default-max-tokens 8192` | 两档无法区分（日常要 131,072/2,048，长档要 262,144/8,192）                                                                                          |
| profiles 的 env 缺 `NINFER_HOST_PAGEABLE`                               | 日志出现 `[ring] host_kv_arena is null … run dense` ⇒ **主机 KV 层不参与降级/检索，长上下文机制等于失效**                                           |
| 默认 `--default-reasoning-effort medium`                                | 短请求 token 全进 reasoning 通道，`content` 为空（实测 `7*5` 返回空）                                                                               |

> **结论：这不是引擎缺陷，是"档位不适配"。** 换档位（参数）即可，不需要换引擎或重编译。

## 2. 两档配方（最终采用）

| 项                     | 日常推荐 `8g-daily`                                    | 长上下文档 `8g-longctx`     |
| ---------------------- | ------------------------------------------------------ | --------------------------- |
| 设备池 `--kv-capacity` | **12,800**（200 页）                                   | **51,200**（800 页）        |
| `--kv-dtype`           | `rk2v4-e8`                                             | `rk2v4-e8`                  |
| `--host-kv-mib`        | **3,328**                                              | **3,328**                   |
| `--max-context`        | **131,072**（2,048 逻辑页）                            | **262,144**（4,096 逻辑页） |
| `--default-max-tokens` | **2,048**                                              | **8,192**                   |
| MTP                    | `--spec mtp --draft-tokens 4 --mtp-attention-window 8` | 无                          |
| 额外参数               | `--no-cuda-graph --default-reasoning-effort none`      | 同左                        |
| 网关输入预算           | 12800−2560 = **10,240**                                 | 51200−8704 = **42,496**     |
| 预算闸门               | **7,421** ≤ 7,488（余 67）                             | **7,312** ≤ 7,488（余 176） |

**实测 `capacity` 行（判据）**：

```text
日常：capacity | KV 12,800 tokens, rk2v4-e8, explicit | pages 200/2,048 | runtime 675.6 MiB | free 340.0 MiB
长档：capacity | KV 51,200 tokens, rk2v4-e8, explicit | pages 800/4,096 | runtime 1.11 GiB | free 310.0 MiB
```

**实测主机层与显存（判据）**：

```text
host state pinned 1.15 GiB + host KV pinned 3.25 GiB（host 8 states, 3.25 GiB KV）
日常：显存峰值 7,015 MiB（红线 7,488，余 473）
长档：显存峰值 7,171 MiB（余 317）
```

> **为什么两档的 `host-kv-mib` 都是 3,328**：262,144 逻辑窗需要 3,296 宿主页；
> 出厂 2,816 只剩 42 页余量，长题面容易撞 429；3,328 给 648 页余量（多占 512 MiB 内存，不占显存）。

## 3. 显存预算账：7421 / 7312 ≤ 7488

启动器在**启动前**就用公式算一遍，超红线**直接拒启**（不会把显存打爆再崩）：

```text
红线 = 卡容量 − 预留 − 桌面 = 8,188 − 400 − 300 = 7,488 MiB
engine = base + pages × slope（ptq1 开 MTP：base 7254；无投机：base 6643；rk2v4-e8 斜率 0.8357 MiB/页）
```

| 档                | 公式                         | 闸门值 |  红线 |    余量 |
| ----------------- | ---------------------------- | -----: | ----: | ------: |
| 日常 `8g-daily`   | 7254 + 200×0.8357 = **7421** |  7,421 | 7,488 |  **67** |
| 长档 `8g-longctx` | 6643 + 800×0.8357 = **7312** |  7,312 | 7,488 | **176** |

**实测峰值低于闸门**（7,015 / 7,171），说明闸门是保守估计，但**不要靠"实测更低"去贴线**：
历史上启动占用有 ±94 MiB 波动，贴线时会偶发拒启。

> **8 GiB 档预留 400 MiB**（用户特批，其余档 500）；桌面 300 MiB 是给 Windows 桌面/浏览器留的。
> 如果你机器上有别的程序占卡，红线不会自动让——先关程序（见 §7 退档阶梯）。

## 4. 六项必须项：症状 → 原因 → 修法

这六项**缺一个就不是本方案**。

| #   | 必须项                               | 不做时的症状                                                                                                                                                             | 原因 / 判据                                                                                                                                          |
| --- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `--no-cuda-graph`                    | 首启 FATAL，引擎日志报 runtime reservation > available                                                                                                                   | CUDA Graph 预留 1,426 MiB，8 GB 卡放不下。加了之后两档都能起（与 v1 同款病根）                                                                       |
| 2   | env `NINFER_HOST_PAGEABLE=1`         | 引擎能起，但日志 `[ring] host_kv_arena is null (pinned host KV reservation clamped to zero). The ring has no demotion target and will run dense.` ⇒ 长上下文机制等于失效 | 10-19 分发包漏带这个 env；上游 2026-10-08 8G 配方明确要求。补上后日志变 `host KV pinned \| 3.25 GiB` + `context cache \| host 8 states, 3.25 GiB KV` |
| 3   | `--default-reasoning-effort none`    | 短请求 `content` 为空（`7*5` 返回空），token 全进 reasoning 通道                                                                                                         | 默认 `medium`；改 `none` 后 `thinking off`，SSE 只出正文。如需思考：客户端带 `thinking_budget`（≥1024）并自行承担速度/额度                           |
| 4   | 日常档 MTP `--draft-tokens 4`        | decode 只有 36~37 tok/s                                                                                                                                                  | 出厂 draft=1；draft=4 提到 **63~72 tok/s**，显存不变（长档不开 MTP，换长上下文）                                                                     |
| 5   | `--max-shared-prefixes 0`            | 环模式下共享前缀快照抛 `active KV snapshot page ownership is not ordered` / `full page is not stable`                                                                    | **启动器强制注入，UI 里不可关**；profile 的 `extra_argv` 也不允许覆盖它                                                                              |
| 6   | 网关 input headroom = 输出上限 + 512 | 网关无法保证"题面 + 输出 ≤ 池"，超池输出可能被静默截断（B35）                                                                                                            | 日常 2,560（usable 10,240）、长档 8,704（usable 42,496）；公式 `池 − headroom`                                                                        |

## 5. 环境变量（4 个，缺一不可）

```bat
set "NINFER_KV_WINDOW=10240"
set "NINFER_KV_RETRIEVE=8192"
set "NINFER_KV_REUSE_HOSTBACKED=1"
set "NINFER_HOST_PAGEABLE=1"
```

| 变量                           | 作用                                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `NINFER_KV_WINDOW=10240`       | **环的门**（常驻窗口）。新件**不再读取** `NINFER_KV_RING`；只设旧 RING 会 CLI 放行 + 引擎 FATAL（B30） |
| `NINFER_KV_RETRIEVE=8192`      | 检索预算（从主机层按内容相关性搬回设备池的页数上限）。**不要删**——历史记录过去掉它会让检索静默答错     |
| `NINFER_KV_REUSE_HOSTBACKED=1` | 允许复用主机层里的检查点（前缀复用入口）                                                               |
| `NINFER_HOST_PAGEABLE=1`       | 允许把页降到主机层；**本方案最重要的一个 env**（见 §4-2）                                              |

> 这些 env 由 `profiles.json` 的 `env` 块统一注入（`launcher.py` 会并入子进程环境），
> 不需要你手工在终端里 set。

## 6. 两档完整引擎命令行（可照抄）

启动器最终拼出的命令（`launcher.py build_argv()`；`<deploy>` = 部署根）：

```bat
:: 日常档 8g-daily（MTP draft4）
<deploy>\10-engine\engines\sm89\infer-serve.exe ^
  "<deploy>\10-engine\model\bonsai2_27b_ternary_ptq1_native_mtp.ninfer" ^
  --host 127.0.0.1 --port 8080 --model-id j27b ^
  --kv-capacity 12800 --kv-dtype rk2v4-e8 --host-kv-mib 3328 ^
  --prefill-chunk 1024 --max-concurrency 1 --derive-session-keys ^
  --presence-penalty 0 --temperature 0.7 --top-p 0.9 --top-k 20 ^
  --default-reasoning-effort medium ^
  --max-context 131072 --default-max-tokens 2048 ^
  --no-cuda-graph --default-reasoning-effort none ^
  --max-shared-prefixes 0 ^
  --spec mtp --draft-tokens 4 --mtp-attention-window 8

:: 长档 8g-longctx（无 MTP）
<deploy>\10-engine\engines\sm89\infer-serve.exe ^
  "<deploy>\10-engine\model\bonsai2_27b_ternary_ptq1_native_mtp.ninfer" ^
  --host 127.0.0.1 --port 8080 --model-id j27b ^
  --kv-capacity 51200 --kv-dtype rk2v4-e8 --host-kv-mib 3328 ^
  --prefill-chunk 1024 --max-concurrency 1 --derive-session-keys ^
  --presence-penalty 0 --temperature 0.7 --top-p 0.9 --top-k 20 ^
  --default-reasoning-effort medium ^
  --max-context 262144 --default-max-tokens 8192 ^
  --no-cuda-graph --default-reasoning-effort none ^
  --max-shared-prefixes 0
```

**逐项说明**：

| 参数                                                   | 值                    | 来自 / 说明                                                                          |
| ------------------------------------------------------ | --------------------- | ------------------------------------------------------------------------------------ |
| `--host` / `--port`                                    | `127.0.0.1` / `8080`  | 只监听本机；**无鉴权，不要改 0.0.0.0**                                               |
| `--model-id`                                           | `j27b`                | 引擎只认这个 id；写别的名字（如 `j27b-long`）→ 404                                   |
| `--kv-capacity`                                        | 12800 / 51200         | 设备池；**可信单题面上限**                                                           |
| `--kv-dtype`                                           | `rk2v4-e8`            | 本模型的 8 GB 档 dtype                                                               |
| `--host-kv-mib`                                        | 3328                  | 主机 KV 预算（不占显存）                                                             |
| `--prefill-chunk`                                      | 1024                  | 预填分块；本机未撞到相关坑，保持出厂值                                               |
| `--max-concurrency`                                    | 1                     | 单路语义                                                                             |
| `--derive-session-keys`                                | —                     | 会话键推导（前缀复用需要）                                                           |
| `--presence-penalty/temperature/top-p/top-k`           | `0 / 0.7 / 0.9 / 20`  | 出厂采样参数                                                                         |
| `--default-reasoning-effort`                           | 先 `medium` 后 `none` | common 里先写 medium，profile 的 `extra_argv` 追加 `none` **覆盖**（同参数后者生效） |
| `--max-context`                                        | 131072 / 262144       | 逻辑窗口；L-01 起按 profile 注入                                                     |
| `--default-max-tokens`                                 | 2048 / 8192           | 服务端默认输出上限；L-01 起按 profile 注入（**客户端仍应显式给**，B37）              |
| `--no-cuda-graph`                                      | —                     | 本卡必需（§4-1）                                                                     |
| `--max-shared-prefixes`                                | `0`                   | 启动器在最后强制追加，并硬断言"恰好一次且 = 0"                                       |
| `--spec mtp --draft-tokens 4 --mtp-attention-window 8` | 仅日常档              | MTP 投机；长档无投机头（权重 5.52 GiB）                                              |

> **不要把 `--max-shared-prefixes 0` 写进 profile 的 `extra_argv`**：它属于受保护开关，
> `launcher.py` 会拒绝（`CONFIG_VIOLATION`），且启动时会硬断言。

## 7. 显存不够时，按这个顺序动旋钮

| 顺序 | 动作                                                                      | 省多少（上游/本机口径）               | 代价                                                                              |
| ---- | ------------------------------------------------------------------------- | ------------------------------------- | --------------------------------------------------------------------------------- |
| 1    | 关掉占卡的其它进程（浏览器硬件加速 / Overlay / QQ / 录屏 / 其它 AI 程序） | **600 ~ 1,000 MiB**                   | 零性能代价，**先试**                                                              |
| 2    | 缩池：每 **−64 页**（−4,096 token）                                       | **−53 MiB**（0.8357×64）              | 可信单题面上限 −4,096 token                                                       |
| 3    | 关 MTP（去掉 `--spec …`）                                                 | **551 ~ 970 MiB**                     | decode 掉到 45~100 tok/s（本机实测无 MTP 约 20 tok/s 是长档池大的形态，短池更快） |
| 4    | `--ngram-draft-tokens 0`                                                  | **50 ~ 127 MiB**                      | 速度 ≈1.01×                                                                       |
| 5    | 降 dtype（`k8v4 → nvfp4 → rk4v4 → rk2v4-e8`）                             | 容量倍率 1.00 / 1.396 / 1.436 / 1.861 | 低档质量**未测**（本方案没走这条路）                                              |
| 6    | 加大 `--host-kv-mib`                                                      | 不省设备显存                          | 解长题面 429（本方案已给 3,328）                                                  |
| 7    | 换档位（日常 ↔ 长档，或减池）                                             | 见 §2                                 | 上限/速度互换                                                                     |

**不要做**：

- 别靠 `--draft-tokens` / `--mtp-attention-window` 省显存（实测仅差 **12 MiB**）。
- 别把池压到 **8 页以下**（启动直接拒：`pool must hold at least 8 page(s)`）。
- 别在长输出场景把 free 页压到 **< 10 页**（历史实测会出现内容缺号/回卷，HTTP 200 但内容是错的）。

## 8. 刻意"没改"的地方（以及为什么）

| 项                                                   | 决定              | 理由                                    |
| ---------------------------------------------------- | ----------------- | --------------------------------------- |
| `NINFER_KV_WINDOW`                                   | 保持 **10240**    | 分发包 profiles 给的值；改了要重验      |
| `NINFER_KV_RETRIEVE`                                 | 保持 **8192**     | 上游警告：动它会让检索静默答错          |
| 采样参数（temperature/top-p/top-k/presence-penalty） | 保持出厂          | 非本方案目标                            |
| `--max-concurrency`                                  | 保持 **1**        | 引擎单路语义                            |
| `--kv-dtype`                                         | 保持 **rk2v4-e8** | 其它 dtype 在 8 GB 档未验/属禁止项      |
| 网关让位阶梯（L0~L3）的参数                          | 不改代码          | 网关是上游件，行为已够用；只调 headroom |
| `--prefill-chunk`                                    | 保持 1024         | 本机未撞到相关坑                        |

### A.2 `launcher.py`（两处）

1. **`build_argv()`**：在 `common_argv` 之后按 profile 注入
   `--max-context <profile.max_context>`、`--default-max-tokens <profile.default_max_tokens>`、
   `profile.extra_argv`；受保护开关白名单禁止出现在 `extra_argv`：
   `--kv-capacity / --max-context / --default-max-tokens / --max-shared-prefixes / --host / --port / --model-id`。
   保留硬断言：`--max-shared-prefixes 0` 恰好一次且 = 0；`--kv-capacity` 等于 profile；
   `--max-context` / `--default-max-tokens` 各恰好一次。
2. **`build_argv()` 追加 `extra_argv` 的顺序**放在 `--max-shared-prefixes 0` **之前**（受保护开关只由 launcher 管）。

3. **`selftest()`** 增补两档断言（示例输出见 [03 · 步骤 3](03-部署路线.md)），防止公式/参数漂移。

### A.3 网关以 `-u` 无缓冲启动（L-03）

出厂 `start_gateway()` 把网关 stdout 重定向到日志文件，Python 非 TTY 时**块缓冲** ⇒ 日志在超时前一直 0 字节，
launcher 的 `pool=(\d+)` 正则永远匹配不到 ⇒ **每次启动都报 `GATEWAY_TIMEOUT`**（引擎其实已就绪）。
改法：`argv = [gateway_python(), "-u", str(GATEWAY), …]`。改后网关日志首行即
`[chatgw] listening on http://127.0.0.1:8081 -> … pool=12800 usable=10240`。

### A.4 校验脚本白名单（L-04 附属）

补丁后 `launcher.py` / `profiles.json` 与 `SHA256SUMS.txt` 不再匹配。
`30-scripts\verify-engine-package.ps1` 已把这两项加入白名单（记 `DEVIATED`），
并用 `_migration-v2\pristine\*.orig-dist` 复核"原件哈希 = 出厂哈希"。
