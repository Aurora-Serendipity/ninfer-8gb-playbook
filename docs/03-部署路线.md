# 03 · 部署路线（从零到可用）

> 本篇是一条**可照做**的路线，每一步都带**判据**。判据不通过就不要往下走——
> 这个项目里绝大多数"莫名其妙"的问题，都是前面某一步没有真正通过。

---

## 路线总览

| 步骤 | 做什么           | 判据                                                         |
| ---- | ---------------- | ------------------------------------------------------------ |
| 0    | 环境前置检查     | 卡是 sm_89、驱动 ≥580、路径纯 ASCII、磁盘 ≥8 GB、内存 ≥16 GB |
| 1    | 获取引擎与模型件 | 两个文件的哈希与长度对得上                                   |
| 2    | 摆好目录结构     | 三层目录就位                                                 |
| 3    | 校验模型件       | `MODELCHECK_VERDICT=PASS`、`LENGTH_MATCH=YES`                |
| 4    | **档位适配**     | 参数按 8 GB 档位设置（见 [04](04-8GB显存档位适配.md)）       |
| 5    | 启动并判活       | `engine ready` + `capacity                                   | ` 行 + **真请求返回** |
| 6    | 跑验收           | `7*5`→`35`；端到端脚本 `RESULT: PASS`                        |
| 7    | 固化与留档       | 记录启动器哈希与实测读数                                     |

---

## 步骤 0 · 环境前置检查

```powershell
# 显卡与驱动
nvidia-smi

# 要看到：NVIDIA GeForce RTX 4060 Laptop GPU / 8,188 MiB / Driver Version ≥ 580
```

| 检查项 | 要求                   | 不满足会怎样                       |
| ------ | ---------------------- | ---------------------------------- |
| 架构   | **sm_89**              | 启动件**直接拒绝**（不是降级）     |
| 驱动   | **≥ 580**              | 有已知兼容问题                     |
| 路径   | 部署根目录**纯 ASCII** | 路径静默乱码，检查全绿但对象不存在 |
| 磁盘   | ≥ 8 GB 空闲            | 放不下引擎 + 模型                  |
| 内存   | ≥ 16 GB                | 主机 KV 层要钉 4 GiB               |

> ⚠️ **跑引擎前先关掉游戏 / 绘图 / 其它 AI 程序**：引擎要 6.6 GB 显存，
> 被占了会启动失败（报 reservation 类错误）。

## 步骤 1 · 获取引擎与模型件

从上游项目获取（地址见 [02 · §7](02-硬件软件基线.md)）：

- 引擎：`ninfer-serve-89.exe` + 同目录的运行期 DLL（含 CUDA 运行库）
- 模型件：`.ninfer` 格式的量化件（本方案用的是 `..._ptq1_native_mtp.ninfer`）

**判据**（必须对得上，见 [02 · §3](02-硬件软件基线.md)）：

| 文件                                         | 字节数        |
| -------------------------------------------- | ------------- |
| `ninfer-serve-89.exe`                        | 1,511,845,888 |
| `bonsai2_27b_ternary_ptq1_native_mtp.ninfer` | 6,394,697,216 |

> 上游还分发过一个**混合目标文件的错误构建**（同名的 exe 但哈希不同，会在特定路径崩溃）。
> **只认哈希，不认文件名。**

## 步骤 2 · 摆好目录结构

```text
<部署根目录>\                       ← 纯 ASCII 路径
├── 10-engine\engine\              引擎 + 运行期 DLL
├── 20-model\models\               模型件
├── 21-launchers\                  启动器（本仓库 scripts\ 里的 *.bat）
├── 30-scripts\                    校验脚本（本仓库 scripts\ 里的 *.ps1）
└── 40-docs\                       文档与实测日志
```

**判据**：`10-engine\engine\ninfer-serve-89.exe` 与 `20-model\models\<模型>.ninfer` 都存在。

> 启动器内部用 `%~dp0..` 定位，所以**目录名可以改，层级不能变**。

## 步骤 3 · 校验模型件

```powershell
powershell -File .\30-scripts\check-model.ps1 -Model .\20-model\models\<模型>.ninfer
```

**判据**：

```text
MODELCHECK_VERDICT=PASS
LENGTH_MATCH=YES
COMPONENTS=mtp,text
HAS_VISION=NO
SPEC_CHOICES=mtp
RECOMMENDED_ARGV=--spec mtp --draft-tokens 4
```

**失败怎么办**：

| 现象                        | 原因       | 处置                 |
| --------------------------- | ---------- | -------------------- |
| `LENGTH_MATCH=NO`           | 下载不完整 | 重新下载，比对字节数 |
| `HAS_VISION=YES`            | 拿错档位   | 换回纯文本档         |
| `SPEC_CHOICES` 里没有 `mtp` | 拿错档位   | 换回带 MTP 头的件    |

## 步骤 4 · 档位适配（**这一步是本方案的核心**）

出厂参数在 8 GB 卡上**起不来**。必须做以下适配——完整依据与代价见
[04 · 8 GB 档位适配](04-8GB显存档位适配.md)。

最小必要集合（**缺一不可**）：

| 改动                   | 从       | 到         |
| ---------------------- | -------- | ---------- |
| `--max-context`        | 262,144  | **65,536** |
| `--kv-capacity`        | 出厂更大 | **4,032**  |
| `--host-kv-mib`        | 16,384   | **4,096**  |
| `--default-max-tokens` | 32,768   | **2,048**  |
| `--gdn-state-fp16`     | 关       | **开**     |
| `--no-cuda-graph`      | 关       | **开**     |

再加两个**零编译的稳定性止血开关**（对付"崩了此后全 503"）：

| 开关                           | 作用                                   |
| ------------------------------ | -------------------------------------- |
| `--recover-invariant-failures` | 不变量失败时尝试恢复，而不是留下僵尸态 |
| `--kv-lease-growth`            | 输出租约按需增长                       |

以及 6 个 `NINFER_*` 环境变量（缺一不可）：

```bat
set "NINFER_KV_WINDOW=16384"
set "NINFER_KV_RETRIEVE=8192"
set "NINFER_KV_RING=1"
set "NINFER_HOST_PAGEABLE=1"
set "NINFER_KV_REUSE_HOSTBACKED=1"
set "NINFER_TERNARY_PTQ1_FAST=1"
```

> ⚠️ **不要删 `NINFER_KV_RETRIEVE`**：上游明确记录过，去掉它会让检索**静默答错**。
> 也不要"顺手调小"——请先看 [04](04-8GB显存档位适配.md) 里那条"池调大反而慢"的实测。

## 步骤 5 · 启动并判活

双击 `21-launchers\start-engine.bat`（它会先检查、再开引擎、最后**真发一条请求**验证）。

**判据（三行都要看到）**：

```text
INFO  engine ready | bonsai2-27b | total 3.3s | weights 5.94 GiB | CUDA sync auto
INFO  capacity | KV 4,032 tokens, k8v4, explicit | pages 63/1,024 | runtime 457.6 MiB | free 560.0 MiB
INFO  listening on http://127.0.0.1:8095 | model qwen3.8-27b | auth disabled
```

外加启动期这两行（证明 KVMem 生效）：

```text
[ninfer] reuse host-backed: on
[ring] content scoring ON by default (the ring is configured): ...
```

> ⚠️ **`/v1/models` 返回 200 不能当作"活着"**：worker 崩掉之后它照样返回 200。
> **必须真发一条请求**（`start-engine.bat` 与 `healthcheck.bat` 都会做）。

## 步骤 6 · 跑验收

### 6.1 能力探针（10 秒）

问 `7*5` 应为 `35`；追加一轮问 `+2` 应为 `37`。

### 6.2 端到端验收脚本

```powershell
powershell -File .\30-scripts\verify-arch-engine-8g.ps1 -Port 8095 -MaxContext 65536 `
  -HostKvMib 4096 -KvDtype k8v4 -SmallPool 2048 -BigPool 8192 -Filler 400
```

**判据**：末行 `RESULT: PASS`，且包含

- 超池告警**正控与负控成对成立**（装得下时 0 行告警，超池时 ≥1 行）
- 中段针 **3/3**、末尾针 **2/2**
- 所有臂的不变量违规 **0 行**

### 6.3 复用判据（两轮）

同一个会话发两条：第二轮应当命中 **`cache ≥ 90%`** 且 **TTFT 降到百毫秒级**。
本机实测 **99.0%（4,061/4,104）+ TTFT 254 ms**。

## 步骤 7 · 固化与留档

1. 记录启动器文件的 sha256（改过就重记）
2. 记录本次 `engine ready` / `capacity` 两行的原文
3. 记录一次计数语料的 `req#N done` 行（这是**唯一**可跨时间比较的性能读数）
4. 把负结果也写下来（哪种改法试过、为什么回退）

> 性能数字**不要跨形态/语料/dtype 比较**；`throughput | 5.0s | ...` 那行是**瞬时值**，
> 权威读数是 `req#N done` 行。

## 常见"卡在某一步"

| 卡在                        | 先看                                                                |
| --------------------------- | ------------------------------------------------------------------- |
| 引擎起不来 / 报 reservation | 是否关了其它 GPU 程序；参数是否按 [04](04-8GB显存档位适配.md) 改全  |
| 起来了但请求无响应          | [07 排错手册](07-排错手册.md) 的"判活"一节                          |
| 能答但答错                  | 是否超池（看日志告警）；最后一条消息是否过长                        |
| 跑一会儿全 503              | 大概率是"超池 + 大输出额度"崩溃 ⇒ 把客户端 `max_tokens` 压到 ≤2,048 |
