# 03 · 部署路线（从零到可用）

> 本篇是一条**可照做**的路线，每一步都带**判据**。判据不通过就不要往下走——
> 这个项目里绝大多数"莫名其妙"的问题，都是前面某一步没有真正通过。

---

## 路线总览

| 步骤 | 做什么                                                  | 判据                                                                  |
| ---- | ------------------------------------------------------- | --------------------------------------------------------------------- |
| 0    | 环境前置检查                                            | 卡是 sm_86/89/120a、驱动 ≥580、路径纯 ASCII、磁盘 ≥10 GB、内存 ≥16 GB |
| 1    | 获取引擎包与模型件                                      | 包可解压、模型件字节数对得上                                          |
| 2    | 摆好目录 + 建模型硬链接                                 | `10-engine\model\*.ninfer` 与 `20-model\models\*.ninfer` 是同一份字节 |
| 3    | **打两档补丁**（见 [04 附录 A](04-8GB显存档位适配.md)） | `launcher.py --selftest` 出现两档 PASS 行                             |
| 4    | 校验包与模型                                            | 包 `RESULT: PASS` + `MODELCHECK_VERDICT=OK`                           |
| 5    | 启动并判活                                              | 一键脚本结尾 `[done] the service is REALLY serving`                   |
| 6    | **四条验收**                                            | 见 §6（真请求 / 能力探针 / 基础验收 / 长输出或针测）                  |
| 7    | 固化与留档                                              | 记录哈希、`engine ready` / `capacity` 两行、一次 `req#N done`         |

---

## 步骤 0 · 环境前置检查

```powershell
nvidia-smi
# 要看到：NVIDIA GeForce RTX 4060 Laptop GPU / 8188 MiB / Driver Version ≥ 580（本机 616.64）
```

| 检查项 | 要求                           | 不满足会怎样                               |
| ------ | ------------------------------ | ------------------------------------------ |
| 架构   | **sm_86 / 8.7 / 8.9 / 12.0**   | 启动器**直接拒绝**（不是降级）             |
| 驱动   | **≥ 580**                      | 有已知兼容问题                             |
| 路径   | 部署根目录**纯 ASCII、无空格** | 路径静默乱码，检查全绿但对象不存在         |
| 磁盘   | ≥ 10 GB 空闲                   | 放不下引擎包（≈2.8 GiB）+ 模型（5.96 GiB） |
| 内存   | ≥ 16 GB                        | 主机 KV 层要钉 ≈4.4 GiB                    |

> ⚠️ **跑引擎前先关掉游戏 / 绘图 / 其它 AI 程序**：引擎要 7 GB 级显存，
> 被占了会启动失败（报 reservation 类错误）。

| `bonsai2_27b_ternary_ptq1_native_mtp.ninfer` | 6,394,697,216 |

## 步骤 2 · 摆好目录 + 建模型硬链接

```text
<部署根目录>\                       ← 纯 ASCII 路径
├── 10-engine\                     ← 解压分发包内容到这一层（含 启动器.bat / launcher.py / profiles.json）
│   ├── engines\sm86|sm89|sm120a\   ← 三份引擎，启动器自动选
│   ├── runtime\                    ← 13 个 DLL + Python 3.12（不要动、不要混用系统 DLL）
│   ├── gateway\ ui\ 工具\ docs\
│   ├── model\                      ← 模型硬链接放这里
│   └── logs\ run\                  ← 启动器创建（日志 / pid.json）
├── 20-model\models\                ← 模型正本
├── 21-launchers\                   ← 本仓库 scripts\ 的 *.bat + 4 个 .ps1
└── 30-scripts\                     ← 本仓库 scripts\ 的 3 个 .ps1
```

**建硬链接**（同一份字节，零额外占用；不要复制两份 6 GB）：

```bat
mklink /H "<部署根>\10-engine\model\bonsai2_27b_ternary_ptq1_native_mtp.ninfer" ^
          "<部署根>\20-model\models\bonsai2_27b_ternary_ptq1_native_mtp.ninfer"
```

**判据**：`fsutil hardlink list <部署根>\10-engine\model\bonsai2_27b_ternary_ptq1_native_mtp.ninfer`
能看到两个路径；或跑 `30-scripts\check-model.ps1`（它把"引擎侧硬链接指向不同字节"判为 FAIL）。

> ⚠️ **不要直接双击 `10-engine\engines\sm89\infer-serve.exe`**：DLL 在包根 `runtime\`，
> 直接双击会 `0xC0000135` 一闪而退、没有任何日志。一律从 `10-engine\启动器.bat` 或 `21-launchers\` 起。
> ⚠️ **整组使用包内 `runtime\` 的 DLL**，不要混用机器上已有的旧 DLL。

## 步骤 3 · 打两档补丁（关键）

出厂分发包**只有五档**（8G 长/快、10G、12G、16G），且 `common_argv` 里写死全局
`--max-context 262144` / `--default-max-tokens 8192`，两档（日常 131,072/2,048、长档 262,144/8,192）无法区分；
网关还需要以 `-u` 无缓冲启动，否则日志 0 字节、启动器永远超时。

本方案给分发包打了**两处最小补丁**（L-01 / L-02，外加 L-03 网关 `-u`），
完整改动、JSON 与回退方式见 **[04 · 附录 A](04-8GB显存档位适配.md)**。

**判据**（补丁正确）：

```powershell
# 在包根跑 launcher 自检（不会启动引擎）
.\10-engine\runtime\python\python.exe .\10-engine\launcher.py --selftest
```

末尾应出现两类 PASS 行（节选）：

```text
PASS 8g-fast pool=12800 gate=7421 MiB ... redline=7488 MiB -> allowed | argv max-shared-prefixes=0 True, kv-capacity ok True
PASS 8g-long pool=51200 gate=7312 MiB ... redline=7488 MiB -> allowed | ...
PASS 8g-daily pool=12800 gate=7421 ctx=131072 default_max_tokens=2048 gateway_headroom=2560 -> PASS
PASS 8g-longctx pool=51200 gate=7312 ctx=262144 default_max_tokens=8192 gateway_headroom=8704 -> PASS
SELFTEST PASS
```

> 自检不通过不要继续——先核对 `profiles.json` / `launcher.py` 是否改全。

## 步骤 4 · 校验包与模型

```powershell
# 引擎包逐文件校验（68 条；本地补丁两项白名单）
powershell -NoProfile -ExecutionPolicy Bypass -File .\30-scripts\verify-engine-package.ps1
# 模型件：字节 + SHA256 + 引擎侧硬链接
powershell -NoProfile -ExecutionPolicy Bypass -File .\30-scripts\check-model.ps1
```

**判据**：

```text
SUMMARY ok=66 mismatch=0 missing=0 deviated=2 unparsed=0      ← 打过两档补丁
RESULT: PASS

[ok] SHA256 matches
[ok] the engine-side path is the same bytes (hardlink)
MODELCHECK_VERDICT=OK
```

**失败怎么办**：

| 现象                                              | 原因                | 处置                                              |
| ------------------------------------------------- | ------------------- | ------------------------------------------------- |
| `MISSING …`                                       | 包解压不完整        | 重新解压，按 `SHA256SUMS.txt` 核对                |
| `MISMATCH engines\sm89\infer-serve.exe`           | 引擎件不对 / 被改动 | 重下分发包；本机应等于 `3B6F9AF9…5EF6E4`          |
| `MISMATCH launcher.py / profiles.json` 但未打补丁 | 文件被改过          | 从 `_migration-v2\pristine\` 或重解压恢复         |
| `MODELCHECK_BYTES` FAIL                           | 模型下载不完整      | 重下，比对 6,394,697,216 B                        |
| `MODELCHECK_HASH` FAIL                            | 拿到别的代制品      | 换回 `bonsai2_27b_ternary_ptq1_native_mtp.ninfer` |

## 步骤 5 · 启动并判活

双击 `21-launchers\start-daily.bat`（日常档）或 `start-long.bat`（长档）。
脚本会：确保控制台（8720）在跑 → 预检预算闸门 → 启动引擎（8080）与网关（8081）→ 轮询就绪 →
**真发一条请求**证明服务可用。

**判据（结尾这几行）**：

```text
[ok] budget gate: engine=7421 MiB, redline=7488 MiB
[ok] engine and gateway are up.
[proof] content = "OK" finish=stop
[done] the service is REALLY serving. You can close this window.
```

启动引擎日志里应有三行"身份自证"（详见 [07 · 日志怎么读](07-排错手册.md)）：

```text
engine ready | bonsai2-27b | … | weights 5.94 GiB | …
capacity | KV 12,800 tokens, rk2v4-e8, explicit | pages 200/2,048 | runtime 675.6 MiB | free 340.0 MiB
[ring] budgets … sum==pool: yes
```

> ⚠️ **`/v1/models` 返回 200 不能当作"活着"**：上游账本记录过 worker 崩掉之后它照样返回 200。
> **必须真发一条请求**（一键脚本与 `healthcheck.bat` 都会做）。
> ⚠️ **网关 8081 不实现 `GET /v1/models`（501）**，判活请打引擎 8080。

## 步骤 6 · 四条验收

### 6.1 第一条 · 真请求判活

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\21-launchers\healthcheck.ps1
```

**判据**：末行 `[PASS ] the engine is really serving.`

### 6.2 第二条 · 能力探针

问 `7*5` 应为 `35`；同一会话追加 `+2` 应为 `37`（第二条带上一轮回答作 assistant 消息）。

### 6.3 第三条 · 运行中两档基础验收（脚本化）

```powershell
# 先启动对应档位，然后：
powershell -NoProfile -ExecutionPolicy Bypass -File .\30-scripts\verify-v2-basic.ps1 -Tier daily
powershell -NoProfile -ExecutionPolicy Bypass -File .\30-scripts\verify-v2-basic.ps1 -Tier longctx
```

**判据**：末行 `RESULT: PASS`。脚本检查：launcher profile 与进程、`/v1/models`、显存红线、
真请求、`7*5→35`、`+2→37`、4 条互异请求、`capacity` 行与档位一致。

### 6.4 第四条 · 长输出 / 上下文针测（可选，慢）

```powershell
# 长输出：目标 2048（日常）或 8192（长档），会跑几分钟
powershell -NoProfile -ExecutionPolicy Bypass -File .\30-scripts\verify-v2-basic.ps1 -Tier daily -OutputTokens 2048
```

**判据**：`completion ≥ 0.9 × max_tokens` 且 `finish=length`（本机实测两档都能吐满）。
上下文针测属研究级夹具，本仓库只记录本机一次单针结果（[05 · §5](05-实测数据与验收.md)），**不列为日常必过项**。

## 步骤 7 · 固化与留档

1. 记录引擎包与模型件的 sha256（改过就重记）。
2. 记录本次 `engine ready` / `capacity` 两行原文。
3. 记录一次计数语料的 `req#N done` 行（这是**唯一**可跨时间比较的性能读数）。
4. 记录显存峰值（`nvidia-smi` 采样）与 decode / prefill。
5. 把负结果也写下来（哪种改法试过、为什么回退）。

> 性能数字**不要跨形态/语料/dtype 比较**；`throughput | …` 那类行是瞬时值，
> 权威读数是 `req#N done` 行与客户端 `usage`。

## 常见"卡在某一步"

| 卡在                                      | 先看                                                                             |
| ----------------------------------------- | -------------------------------------------------------------------------------- |
| launcher 自检两档 FAIL                    | `profiles.json` / `launcher.py` 补丁没改全（[04 附录 A](04-8GB显存档位适配.md)） |
| 引擎起不来 / 报 reservation               | 是否关了其它 GPU 程序；`--no-cuda-graph` 是否在命令行里                          |
| 启动脚本报 `GATEWAY_TIMEOUT` 但引擎已就绪 | 网关没有 `-u` 无缓冲启动（L-03）                                                 |
| 起来了但请求无响应 / 正文为空             | 思考档是否为 `none`；看 [07 排错手册](07-排错手册.md) 的"判活"与"空回答"两节     |
| 能答但答错                                | 是否超池（看日志 `unverified` 告警）；题面是否超过池                             |
| 跑一会儿 429                              | B33：连续长请求后上下文缓存排不下 ⇒ 停/启引擎                                    |
| 输出写一半停了                            | 客户端是否显式给 `max_tokens`（B37）；题面+输出是否超池（B35）                   |
